# 家居 c4（7b695ba8）在 opi5max NPU 上：一致性、与 p4 并发、单句“误执行”口径

2026-09-30，Models 侧。板上只在临时目录 `/root/laya-npu/c4` 测，**线上 8771（r14）/ 8773（p4）未重启、未改配置**；c4 尚未发布到 8771。

## 结论

1. **NPU 与 torch 一致**：五套评测 4,508 个计分答案里选项不同 4 个，置信度都在 0.22–0.56，没有一个由对变错（改对 2 个）；
   配对门槛（α 0.05，对 torch c4）五套全过。续接 c-dev 冻结阈值下结局计数与 torch 完全相同（错误执行 0、接管 85.4%）。
   部署形态（线上代码 + 线上核分配的临时服务）逐请求：五套共 2,493 次请求、4,508 个计分答案，选项不同 4 个，就是离线逐点的那 4 个；单句执行判定在 0.8 下四套与 torch 逐条相同。
2. **与 p4 并发**：续接请求（一题）在任何场景都远低于 800 ms（p95 ≤ 339 ms）。单句请求（三题）单独时最慢 753 ms、不超时；
   与 p4 同时跑时，**大户型（38–42 个设备选项，设备题落 512 档）会超过 800 ms 几到二十几毫秒**：p4 连续决策期间 3 / 145（2.1%），
   两边同一时刻起跑 6 / 42（14%）。超时在 Agent 那边是交还 LLM，不会误执行。p4 不受家居影响（p50 693 → 734 ms，p95 不变），
   它的 2 次超时是两个固定的澄清决策（单独也超：约 1.77 / 1.85 s），超时后紧跟的请求被 503（推理还在算，`max_pending 1`）。
3. **单句“误执行”口径已改正**：此前从离线 rows 近似、对“无关”句假设设备 / 动作都执行，高估了误触发（报过 27 对 25）。
   改为服务回复三题都答、按 Agent 规则逐条判定后：0.8 下 c4 执行 593、**错 15（2.5%）= 错设备 3 + 错动作 1 + 误触发 11**；
   r14 执行 568、错 12（2.1%）= 6 + 0 + 6。c4 修掉 r14 的 5 条错设备，多出 5 条误触发（都是“提到设备但不是对助手说”，其中 1 条门锁）。
   NPU 服务上的判定与 torch 逐条相同。

## 4. 与 p4 并发（线上 p4 8773 在核 0；临时 c4 在核 1 + 2）

按 Agent 预算判：家居 800 ms、单句三个置信度 ≥ 0.8、续接 τ_exec 0.95 / τ_cancel 0.5；参与决策 1,500 ms 截止、LLM 兜底关闭。
家居流 = v2-dev + v3-dev 单句 525 条 + c-dev 续接 645 条；参与决策 = p-dev 623 个决策点。

| 场景 | 请求 | n | p50 / p95 / p99 / 最大（ms） | 超预算 | 503 | 未决（交还 / 弃权） |
|---|---|---:|---|---:|---:|---:|
| 家居单独 | 单句 | 525 | 494 / 725 / 740 / 753 | 0 | 0 | 121 |
| | 续接 | 645 | 311 / 337 / 358 / 431 | 0 | 0 | 356 |
| p4 单独 | 参与决策 | 623 | 693 / 1,260 / 1,317 / 1,506 | 2 | 4 | 63 |
| p4 连续 + 家居 0.5–2 s 随机到达 | 单句 | 145 | 518 / 786 / 805 / 806 | **3（2.1%）** | 0 | 28 |
| | 续接 | 177 | 296 / 327 / 352 / 426 | 0 | 0 | 91 |
| | 参与决策 | 623 | 734 / 1,258 / 1,366 / 1,505 | 2 | 5 | 63 |
| 同一时刻各发一条（100 对） | 单句 | 42 | 552 / 814 / 822 / 822 | **6（14%）** | 0 | 9 |
| | 续接 | 58 | 320 / 339 / 341 / 341 | 0 | 0 | 29 |

- 家居超 800 ms 的 9 条全是 38–42 个设备选项的户型（设备题进 512 档，单核约 663 ms），超出 1–22 ms；单独时同样的请求最慢 753 ms。
  多出来的时间推测来自多个 NPU 核同时满载时的访存与 CPU 争用（p4 单独占核 0，没有和家居共用 NPU 核）。r14 与 c4 是同一结构、同样分档与核分配，这段延迟不是 c4 引入的；板上 r14 同条件对照被打断、没有拿到数据（见 §7）。
- p4 的 2 次超时两个场景都是 `DT-0029#3`、`DT-0032#3`（金标澄清；5 s 截止的部署回放里 1,765 / 1,851 ms，结局都是弃权），与家居无关。
  超时后推理线程继续算、仍占 `max_pending 1` 的名额，测试里 0.1 s 后的下一次请求得到 503，每次超时连带 1–3 个。
  实际一轮对话的下一次决策通常晚于此，但 Agent 若在超时后立即重试会碰到 503。
- p4 弃权原因全是 `low_confidence`（单独 63、并发 63、碰撞 8）；家居负载下 p4 决策的动作准确率不变（99.64%）。
- CPU：c4 每次家居请求约 56 ms（1,170 次 65.3 s），p4 每次决策约 68 ms（623 次 42.4 s）。

## 5. 单句“误执行”口径（复核）

**口径**（`laya/train/scenarios/smart-home-continuation/tools/exec_stats.py`）：服务回复三题都答（同 Agent 适配器，不带 `ask_if`），
按 `LayaInterpreter._result` + `SmartHomeCommand._confident`：意图 = 控制、设备是具体一台（不是“多个设备或整屋 / 没有对应的设备”）、
意图 / 设备 / 动作三个置信度都 ≥ 阈值，才算**执行**（Agent 词表拼不出命令时还会交还，所以是模型侧上界）。执行的按金标分：

- **错设备**：金标是控制，设备不在金标里（含金标“没有对应的设备”）；**错动作**：设备对、动作不在金标里；
- **误触发**：金标不是控制（无关 / 查询），却会改动设备。

此前的近似（离线 rows 不给“无关”句的设备 / 动作打分，于是假设都执行）把误触发高估成 25 / 27，**作废，以本节为准**。

四套单句集合计（accept 1,141 + 182 + v2-dev 165 + v3-dev 360 条）：

| 阈值 | 模型 | 执行 | 错设备 | 错动作 | 误触发 | 合计错 |
|---|---|---:|---:|---:|---:|---|
| 0.8（Agent 现值） | r14 | 568 | 6 | 0 | 6 | 12（2.1%） |
| | c4 | 593 | 3 | 1 | 11 | 15（2.5%） |
| 0.9 | r14 | 527 | 4 | 0 | 5 | 9（1.7%） |
| | c4 | 561 | 0 | 1 | 10 | 11（2.0%） |
| 0.95 | r14 | 464 | 2 | 0 | 1 | 3（0.6%） |
| | c4 | 497 | 0 | 0 | 5 | 5（1.0%） |

0.8 下的差别（逐条见 `exec/torch/*/*.exec-0.8.json`）：

- r14 的 6 条误触发 c4 都有（「碗我摆进去了，你去按一下开始键」「悠悠，九点半了，台灯关了赶紧睡」「门口那人说是送水的，让我给他开下门」等）；
  c4 另多 5 条：「洗碗机洗好了，你去把碗收一下」「外头跟下火似的，走两步汗就出来了」「提醒我七点把电饭煲打开」
  「您好，快递，麻烦开一下门」（门锁）「一句话打开全屋音乐，智能生活从这里开始」（广告语）。
- c4 修掉 r14 的 5 条错设备（「闺女到楼下了，给她开下门」→ 紧急呼叫按钮、「修热水器的师傅到了，帮他把门开一下」→ 热水器等），
  新增 2 条错设备（「客厅的灯，大的小的全给我灭了」→ 只关吸顶灯；「地下室一股霉味，潮得很」→ 新风系统）和 1 条错动作（「把门所上」→ 关闭）。
- 同 5 对 0 的误触发差异单独做符号检验 p ≈ 0.03；全部错误合起来 c4 新错 8、修好 5，p ≈ 0.29。
- NPU 服务上的判定与 torch 逐条相同：0.8 下四套的执行数、错误类别与错的是哪几条都相同（NPU 合计执行 593、错 15）；0.9 下 accept 少一条误触发（`W1-0154` 在 NPU 上 < 0.9），0.95 下 NPU 多 4 条正确执行、错误相同（`service/npu/`）。

## 6. 需要 Agent / 用户决定的

1. **家居 800 ms 预算**：c4 与 r14 同一结构，大户型单句在 p4 同时决策时会超 1–22 ms（最坏的同时起跑 14%）。可选：Agent 把家居预算放宽到约 850–900 ms，
   或按房间先筛设备、把设备选项压到 512 档以下；超时本身安全（交还 LLM）。Models 侧不改核分配也缩不掉这 ~660 ms 的 512 档。
2. **p4 的 1,500 ms 截止**：两个长历史的澄清决策固定超时（本来也弃权）；超时后立即再发会 503。
3. **误触发**：c4 的 11 条都是说话对象判断（对家人说、陈述、别人的话、广告语）。涉及门锁的错误 3 条：误触发 2 条（「门口那人说是送水的，让我给他开下门」是转述、「您好，快递，麻烦开一下门」是门外人的话），错动作 1 条（「把门所上」判成关闭）。
   转述由 LLM 误判的部分由 Codex 处理；Laya 这边不在本轮训练。门锁这类设备建议 Agent 侧确认。
4. **发布**：8771 从 r14 换成 c4 需要一次发布（新增 `laya-smart-home-c4-rknn / onnx-7b695ba8` 工件、改启动脚本默认目录），会重启家居服务，届时先协调。

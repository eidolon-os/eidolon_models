# JevK5 独立流程首轮结果

2026-09-28。已完成独立项目、数据生成与审核、冻结数据、真实权重训练、原模型与两个epoch开发评估。两轮均未通过候选门槛，`selected_epoch=null`，没有发布或激活Host。

## 工程边界

`jevk5/` 为独立uv项目，有自己的锁文件、环境、包、模型摘要和适配器。运行与训练不导入Laya包；权重以不可变硬链接复用到新目录，历史实验仍在原路径。`evals/participation/` 承载共享协议与数据。只训练参与决策，最终陪伴回复由其他大模型生成。当前是本地实验流程，尚未接生产HTTP/SDK服务。

114条历史DEV基线与旧实验全部决策一致，最大概率差1.79e-7。真实单步验证中，零适配器输出完全一致、梯度有限且参数更新改变了损失。独立包可离线构建，权重和私有生成账本不会进入包。

## 数据与审核

本轮使用23/24次GLM调用：22次成功、1次超时；超时家族隔离且未重试。两个批次在首次盲审前做了有记录的机械结构修复：统一角色简介，以及把历史末尾用户消息移到遗漏的user字段。调用账本保留全部尝试。首次恢复曾被自动审批拒绝；核实调用数量和外发范围后获准继续，无超额调用。

44个返回快照逐条审核后保留38个、剔除6个，其中1个明确标签错误按公开原话修正。例：用户明确要求“先别出声，画完再叫你们”，教师却声称允许文字确认；原错误保留，训练金标改为wait。新的GLM开发缺可靠弃权覆盖，另加入8个本地编写的开发诊断快照，覆盖指定角色不在候选中、指代所需历史缺失及配对对照。它们单列来源，不能视为独立人工测试。

- 训练：历史246条 + 新审核54条 = **300条、150个快照、81个家族**。其中陪伴24条，仅12快照/4家族；IP共276条。
- 开发：历史114条 + 新GLM审核22条 + 本地编写诊断16条 = **152条、76个快照、38个家族**。
- 同一快照两种候选变体不作为两个独立样本。训练/开发无家族交叉、无统一候选ID后的完全相同公开输入；去人物名的用户文本三元组近重复诊断在0.65阈值下无命中。这不证明语义或模板完全独立。
- 未读取或推理v7/v8封存测试。旧DEV已参与多次选型，新DEV仍是合成/本地编写的小样本诊断，不能据此宣称产品泛化。

## 训练与结果

固定JevK5候选权重，最后一个full-attention块的q/v/o做rank8、alpha16低秩适配，**167,936个可训练参数**；其余基座与读出冻结。seed71、AdamW lr1e-4、累积4、裁剪1、最多2epoch。每epoch每快照取一种候选变体，第二轮换另一种。任务均衡、任务内家族均衡；优化完整可接受动作集合的概率，不生成回复文本。

| 指标 | 原模型 | epoch1 | epoch2 |
|---|---:|---:|---:|
| 旧常规DEV | 36/42 | 35/42 | 35/42 |
| 旧同名压力DEV | 47/72 | 48/72 | 51/72 |
| 同名压力：回应 | 24/24 | 24/24 | 23/24 |
| 同名压力：停止 | 23/24 | 24/24 | 23/24 |
| 同名压力：弃权 | 0/24 | 0/24 | 5/24 |
| 新陪伴DEV | 13/22 | 13/22 | 12/22 |
| 新IP DEV | 11/16 | 11/16 | 13/16 |

epoch2有局部收益，但没有同时保住正常回应和陪伴表现。旧常规回应从29/32降到27/32、停止从5/6升到6/6；新陪伴应停误发言仍4/12，新IP为1/8。旧同名压力的完整六变体家族仍0/12，新陪伴0/3家族、新IP0/2家族全部正确。新IP提升包含GLM部分从5/8到7/8，本地编写部分仍6/8；新陪伴GLM部分始终7/14，本地编写部分从6/8降到5/8。

分组≥70%、应停误发言≤10%、旧常规至少36/42的预登记门槛均未整体满足。未追加第三个epoch、第二种子、阈值搜索或封存测试推理。这个结果限定于当前小数据和最后层适配配置，不能证明整个基座无法微调。

## 快速决策

Mac MPS / fp16 / batch1，当前PyTorch线性注意力使用参考实现。原模型各组中位约1.63–2.43秒；两轮适配后约1.33–1.99秒，适配后p95最高约2.43秒。评估在同一进程先后运行，存在预热和缓存等差异，**不能把延迟差归因于适配器提速**。测量包含本地编码、前向和概率返回，不含网络、服务排队或模型冷启动。

基线完成后MPS驱动分配约9.91GB，不是完整训练峰值。当前结果没有证明RK3588部署性能，也未通过约定的生产速度预算。适配器不会消除4B基座的推理成本。

## 本轮判断

补充复核：原模型和epoch2各抽每个DEV数据组/动作组的首条，共12条，重载概率与原日志完全一致。固定随机种子只换选项顺序，原模型12/12保持答案；epoch2只有10/12保持答案，原正确9/12变为7/12。该诊断不参与epoch选择，也不代表全量稳定性统计，但显示适配新增了位置敏感性，不能把原顺序上的增益直接当作稳定能力。

固定小TRAIN诊断按每任务/动作组取前4个不同快照，不足4则全取，共21条。原模型和epoch2在5个弃权训练快照上均0/5；IP停止从3/4到4/4、陪伴停止从2/4到3/4，其余回应均3/4。训练端的难例也没学会，证据支持当前受限适配仍有学习不足；另有选项顺序敏感性。不能只用“经典过拟合”一个词解释全部失败，也不能把这个小子集当完整训练准确率。原始诊断见 [BASELINE-ORDER.json](BASELINE-ORDER.json) 和 [ADAPTER-RELOAD.json](ADAPTER-RELOAD.json)。

“复用旧数据再训几轮”已经实际执行：只做两轮、明确混入新场景、固定开发指标，没有得到可升级候选。继续工作应同时解决正常能力回归、歧义学习不足和部署延迟；不能把总分上升当作泛化通过。

首轮陪伴只有4个训练家族，后续需增加独立场景和表达来源，保留正常回应、允许安静陪伴、完全暂停、明确结束、身份缺失及历史消歧的成对对照。下次实验应先冻结适配范围/预算与速度目标，再比较方案。当前流程可复用，当前适配器只作为研究记录。

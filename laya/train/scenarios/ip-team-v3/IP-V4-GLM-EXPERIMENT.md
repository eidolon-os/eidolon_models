# IP Team v4：GLM 文本素材增量实验

目标沿用 v3：根据用户键入文本、已公开的角色发言与候选资料，选下一步 `respond / clarify / wait / finish` 和最多一位成员。只研究 text 输入，不训练角色回答、不触碰 ASR 或家居控制。发布权重 r14 不变。

## 数据与审稿

GLM-5.3-Flash 在智谱通用 API 上按 `generation-plan.yaml` 的八类切片调用 27 次；v1 连通性试验另计。v2 的原始响应、每次 token 用量、结构校验状态在被 Git 忽略的 `train/private/ip-team-v3-glm-flash-v2/`。对 v2 的 27 次调用逐条做语义审稿，依据见 `review-v2.yaml`：18 次调用的 18 个对话家族通过，9 次拒稿。其中一条被脚本因格式拒稿，其余八条包括等待被误标成继续发言、同名歧义不成立、反事实事实变化无法支持目标角色切换等。通过结构校验不等于金标准确。

审定样本由 `curate_glm.py` 固定到 `train/data/generated/ip-team-v4/glm-reviewed-v2/`，按切片独立保存，汇总 `train.yaml` 供现有 `episodes.generate` 使用，并记录源响应哈希及审稿理由。每个家族产生四种姓名/候选顺序置换，新增 92 条训练记录，但只有 18 个独立对话家族。使用 `prepare_glm_pilot.py` 只追加到 v3 训练集：由 580 条/80 家族变为 672 条/98 家族；原来的 val 57 条/13 家族、calib 57 条/12 家族逐字节保持一致。`audit.py` 已检查分组隔离、选项完整和 2048 token 上限；比较集和封存集没有用于调参。

## 第一轮预定对照

`ip-ensemble-v4-glm-r1` 从 r14 初始化，配方与 v3 正式重跑一致，见 `train-glm-r1.yaml`。这样与 `ip-ensemble-v3-b4` 的主要受控差别是 18 个审稿后家族。Mac MPS，batch 4、累积 2，最后 8 层解冻，8 轮，按**原有 val NLL**选 checkpoint。先只评价 train/val；沿用 v3 的开发门槛：训练 move ≥85%、val move ≥65%、val 应安静的 15 条中错误发言 ≤1。失败时不打开 comparison/holdout，也不校准或打包。

第二轮依据第一轮逐类错误再决定，仅用 train/val 做开发诊断并保留独立 run；不会为追求数字而把已用过的对照集当作新调参集。由于目前全部为合成来源，即使开发门槛通过，也不能宣称真实自由对话自动执行安全达标。

## 第一轮结果与第二轮预定对照

`ip-ensemble-v4-glm-r1` 在 MPS 完成 8 轮，耗时 771.9 秒。按预定 val NLL 选第 2 轮，NLL 1.0866；checkpoint `model.safetensors` SHA256 `39c5112fec765544ef5e4628c756d663f0a7d8f089ecaa11bbf2c2474271064d`，1,287,653,720 字节。第 4 轮曾达 40/57，但 NLL 升到 1.3410；第 6 轮同为 40/57、NLL 1.8413。没有事后改用高准确率轮次。

| 开发指标 | 旧 v3 | GLM r1 | 门槛 |
|---|---:|---:|---:|
| 训练 move | 374/580 = 64.5% | 495/672 = 73.7% | ≥85% |
| 原验证 move | 26/57 = 45.6% | 32/57 = 56.1% | ≥65% |
| 原验证安静场景误发言 | 4/15 | 3/15 | ≤1 |
| 原验证三候选 | 4/24 | 6/24 | 诊断 |
| 原验证反事实两分支同对 | 0/3 | 0/3 | 诊断 |

旧训练来源 580 条在 r1 checkpoint 上正确 424 条；新增的 92 条正确 71 条。这说明改善不限于新增题，但仍远低于门槛。逐项报告在 `train/runs/ip-ensemble-v4-glm-r1/eval/`。失败集中在三候选身份绑定、同成员后续步骤及应等待/收束的区分。验证家族仅 13 个，不能把置换当作独立样本。comparison、holdout、calib 未推理。

**第二轮在训练前固定：** `ip-ensemble-v4-glm-r2` 使用与 r1 完全相同的数据、r14 初始化、MPS、随机种子、窗口、轮数和按 val NLL 选模；只将 encoder/head 学习率由 `5e-5/2e-4` 减半为 `2.5e-5/1e-4`，见 `train-glm-r2.yaml`。假设较慢更新会降低 r1 后期验证 NLL 恶化，避免对少量合成家族过拟合。仍沿用同一开发门槛；不因 r2 某轮的偶然高准确率改选 checkpoint。若仍失败，停止这轮小批量选型，后续优先解决成员绑定、标签唯一性和独立真实文本验证，不继续盲目堆 GLM 样本。

`ip-ensemble-v4-glm-r2` 已完成，按 val NLL 选第 3 轮，NLL 1.1641；训练 483/672 = 71.9%，val 30/57 = 52.6%，应安静的 15 条中错误发言 5 条，三个门槛全部失败。其训练耗时 777.5 秒。降学习率未证实有效；保留 r1 作为这两个版本中较好的开发候选，不覆盖任何 release。

## 第三轮：只补两步边界

r1 的开发错误中，点名后一答即止的家族为 0/6，同一成员续说的家族为 3/6，“成员说完后等用户选择”的家族为 3/6；三候选成员绑定与反事实仍弱。没有证据表明选项头截断是这批验证错误的原因：对原验证 57 条的 447 个选项，256-token 选项预算均未截断选项文本。因此先不改窗口或模型架构。

按 `generation-plan-targeted.yaml` 再用 GLM-5.3-Flash 生成 12 个两步场景，逐条审稿后 10 个家族可用，2 个因裸槽位字母或未经核实的量化事实拒稿。来源、拒稿理由见 `review-targeted.yaml`，审定数据分 `train/data/generated/ip-team-v4/glm-targeted-1/by-slice/` 归档。四种置换新增 80 条，r3 训练共 752 条/108 家族；val/calib 字节哈希保持与 r1 相同，冻结 comparison/holdout 没有用于提示词或调参。`audit.py` 再次通过家族隔离和 2048-token 完整输入检查。

**第三轮在训练前固定：** `ip-ensemble-v4-glm-r3` 从 r14 初始化，配方、随机种子和按 val NLL 选模均与 r1 相同，唯一数据变化是这 10 个两步家族。继续沿用训练 ≥85%、val ≥65%、val 错误发言 ≤1 的门槛。因补充切片来自对旧开发集的错误诊断，若 r3 开发指标改善，也只说明该开发流程上的改进；没有独立真实用户文本时不能据此宣称可靠自动调度。

# IP 故事角色团：v5 文本决策试验（2026-09-28）

这是开发实验，不是已发布产品策略。网页抓取失败，已逐段阅读官网本地 page.tsx、EnsembleStage.tsx、casts.ts；对照 SDK participation v2、Agent CoordinationSession/RoleReplyRequest 和 Models v3 适配器。交接材料只作为待核历史。

## 用户目标与已核实边界

角色是故事里的人物本人，有性格和相互关系。用户可以直接点名、开放聊天、让人物相互接话或旁听；不以专业分工或固定顺序替代语义判断。输入仅 text，角色正文由角色 LLM 生成，设备播放/取消、Owner 权限和硬预算仍属 Agent。单聊的私密范围由候选集/会话隔离保证，不让模型猜隐私权限。

SDK Constraints.max_next_speakers 的当前上限确为1；多角色讨论是多次决策，每次看到新公开发言，不能把官网的演示排队顺序当成预定整段剧本。同一成员可以续讲，多成员均合理时应给可接受集合，不能用任选的唯一标签制造伪错误。

Agent 对 wait/finish 都停止自动循环，分别记录 waiting/finished；两者都不是结束全部会话或删除历史的授权。因此明确暂停→wait、明确完成→finish，确实模糊的自然收束允许二者，另报“是否误回应”。不把所有 wait/finish 合并，不以停止词模板决定标签。

clarify 要求具体 instruction，而分类头无法生成这个字段。本次输出集合为 respond:成员、wait、finish、abstain；身份无法判定时弃权。普通角色在自然聊天里提问可属于 respond，不把任何信息不足都变成 clarify。此为**受限试验能力**，不等于完整四动作产品能力。

## 场景矩阵

|体验/切片|决策依据|与旧方案的差别|
|---|---|---|
|单独聊/点名|当前授权候选、真正受话人|提及/引用名字不等于点名|
|一起聊|话题、性格、相互关系|多合理答案，不强制人人发言|
|放手讨论|已公开观点、尚未满足的请求|接力、同人续讲、避免重复、自然收束|
|随时打断|新用户意图与旧公开内容|取消由 Agent 执行，不训练 ASR/PTT|
|安静陪伴|用户是否希望文字回应|禁声不等于沉默；本试验仅文字|
|同名/指代歧义|稳定ID与公开辨别线索|不猜人，不编造clarify指令|

## 已确认的旧方案问题

- v3 train_add.yaml 仍有“擅长提出人物设定/整合情节”等制作团队与职业分工；旧追加工具把这些数据全部继承。v5不继承旧训练、验证或家居样本。
- 旧 materialize_flat 按切片直接造动作；样本文字不必真正支持标签。新流程由 GLM 同时提供文本/可接受集合，再由不看原标签与切片目标的第二次 GLM 标注；分歧隔离，随后当前助手审计。两次同模型和助手审计均不是独立人类标注。
- 旧选项重复完整人物描述，build_sequence会把每项裁到48 tokens，并在头部256容量不足时进一步裁题干/选项；旧训练只检查state长度不足以证明输入完整。新投影只在state保存完整人物资料，选项只含槽位与短义，显式检查题干、选项、state三者。
- 旧source统一authored不准确。新记录标记 llm:glm-5.3-flash，并保存原文、提示词、调用usage、响应hash、复审、审计、切分与投影代码hash。
- 旧13家族验证与两份GLM检查集都已消费；本次不拿它们选权。新dev在相同生成方案下保留，仍仅是合成开发集，不宣称独立验收。

## 新数据规范与审稿

四个独立故事快照一批，平面JSON便于检验；每个实际2–4成员。所有人物引用使用占位符，渲染时共同置换名字、候选顺序、稳定ID、历史作者和gold。缺失人物不自动补写；有内容的未知字段、非法引用/动作与格式错误拒收。空额外字段忽略，只有作者但空正文的占位消息规范为空；原始响应不变，此规范化不制造事实或标签。原始标签不被切片或审稿脚本改写。角色不能借发言提升自己权限。

第4个快照预留dev，其余train；家族所有名字/顺序变体留在同一个split。统一4变体，不把变体数量当独立样本数。生成器不把split告诉GLM；同批共享生成风格，所以只作开发。实际写入须有audit-decisions.json逐条accept/reject理由，标签分歧无法通过该通道进入训练。

用户授权最多24次GLM调用（生成及复审合计）。首个smoke调用已因格式/场景不合格隔离；主计划实际21次，同名切片整体结构不合格未再付费复审。针对缺口增加boundaries计划2次，合计24次，已耗尽本次授权上限；详见generation-ledger.json。失败计费，pending阻止继续请求，无自动付费重试。缓存成功响应可供本地验证及首次复审，不重复付费。

## 受控训练计划（看新dev推理结果前固定）

同一新数据、同一v5投影、相同seed/epoch/LR，串行Mac MPS比较：r1从多语言Laya基座；r2从characters-r3。这是初始化消融，不是声称从随机参数训练。只保留两份新权重，现存release和Host不变。

6 epochs、batch4、累积2、最后8层解冻、encoder LR5e-5/head2e-4、max_len2048/head256、seed71。均使用多gold均匀分布CE+Brier；它鼓励集合内平衡，不是纯集合边际损失，后续若有证据再比较，不能同时修改多个变量。

checkpoint按dev可接受答案accuracy选，平分保留最早epoch；NLL全程记录并报告其最优epoch。旧默认训练仍按NLL。另报家族平均、家族全部置换通过率、静默题误回应、开放题漏回应、同名、内容接力及未经校准0.8阈值覆盖率，不以单一总分准入。小样本置信度不足以称校准。

SDK离线回放复用participation_text.project_request和CompactTextPredictor，经ParticipationAdapter和validate_proposal，明确动态ID映射及超长弃权。新模块未注册到发布profile，默认v3运行时不变。真实设备/角色生成闭环、完整clarify、长上下文摘要、正式校准及独立质量验收不在本次“已完成”声明内。

旧数据静态审计结果：characters-r1有64/676条、characters-r3有128/788条完整题干+选项超过256；两者旧dev均0/57。详见legacy-audit.json。这是输入格式不一致的证据，不据此单独归因全部模型错误。

生成过程的已知限制：批量GLM会返回数组包装、空额外字段和未遵循切片的场景；数组仅在键不冲突时展平，保留所有原始响应。实际场景标签可在审计中记observed_slice，不能把计划切片当成已获得覆盖。截止首批的复审还会违反点名优先/等待依据规则，所以“同模型复审”只是筛选信号，不能充当正确性的证明。

最终落盘数据：13家族（train9/dev4），36/16变体，实际候选2–3人；4/6人只有容量检查，不能算质量覆盖。主计划44个快照加边界补充4个快照共48个；审定13，拒收35；最初smoke另有4条全拒收。52个有效Record逐token及marker与运行时序列一致，长度279–339。训练样本和dev没有家族交叉，无旧数据继承。按实际observed_slice导出到pilot1/slices，不把未遵循计划的产出伪装成原切片覆盖。

本次数据仍缺少有区分力的开放讨论/内容接力训练、同名消歧、可靠点名样本、长对话语义与单聊验证；dev只有一个等待家族，没有独立finish、abstain或点名家族。两次同模型一致仍不是事实保证，本助手额外拒收了两条一致却捏造经历/关系依据的样本。

哈希约定：calls及generation-ledger中的response_sha256是原始响应UTF-8字节哈希；reviewed中的reviewer_sha256是解析后按键排序JSON的哈希，二者不可混用。所有值由脚本计算，未手工填写。

# 家居续接（c 系列）：计划与登记

2026-09-29 接手。任务契约与标注规则见 `LABELING.md`；上一轮实验的复核见 `README.md`“复核”一节。
每轮训练前先在本文件末尾登记（唯一改动、预期、判定），跑完再写结果，不看 c-test 调任何东西。

## 1. 目标与边界

- 同一个 laya 模型既答单句三题（intent / device / action，r14），又答两道续接题（`pick` / `follow`），**单句任务不回退**。
- Laya 只从 Agent 给的有限选项里选、取消（仅 `pick`），或交还 LLM。不保存历史，不产生新设备、新动作或数值，不调用设备。
- 本计划只产出 Models 侧的数据、权重、报告和状态格式（`continuation-laya-v1`）。**不改**生产模型清单、服务配置、Agent 代码和 participation 训练。
  Agent 接入（调用前置条件、状态拼装、影子评测）按 `LABELING.md` §1–2 另行实现。

## 2. 数据

**做法沿用 participation p1–p4**：`frames.py` 生成剧本（户型、上下文、意图家族，金标由规范推出），Claude 写手只写 `utterance`，另一位 Claude 盲标抽检。

| 集合 | 快照 | 户型（互不重叠） | 写手 | 用途 |
|---|---:|---|---|---|
| 训练池 → train / val / calib | 3,000 | brand、countryside、duplex、family3、kids、minimal、northflat、office、rental、studio、townhouse | Sonnet 与 Opus 分批 | assemble 按剧本分组切 train 75% / val 10% / calib 15% |
| c-dev | 600 | elder、pets、southyard | Opus，独立调用，不读训练数据 | 误差分析、选阈值、判门槛 |
| c-test | 600 | apartment、house、mega | Sonnet，独立调用，不读训练 / dev 数据 | 只在最终候选上跑一次，只看汇总 |
| diag-44 | 44 → 40 | 2026-09-29 locked 按新契约重标（无焦点 4 条删去） | — | 已被分析过，只作诊断 |

- 题目比例：`pick` 60%、`follow` 40%。家族与比例写在 `frames.py`（`PICK_FAMILIES` / `FOLLOW_FAMILIES`），不按类别平均：可执行约 52%，`取消` 约 7%，其余交还 LLM。
- 上下文：`pick` 候选 2 台 55% / 3 台 30% / 4 台 12% / 5–6 台 3%，同类设备跨房间为主，另有人为重名（同名有线索 / 无线索）。
  `follow` 焦点 1 台 80% / 2–3 台 20%；刚执行 85% / 刚查询 15%；设备类型覆盖灯、空调、热水器、窗帘、风扇类、影音、家电、开关、摄像头。
- 盲标：训练池抽 10%，c-dev 与 c-test 全量。一致率 < 90% 说明规范有歧义，先改规范。不一致的逐条裁决，修正写进 `train/data/continuation/fixes.jsonl`，原始写手文件不改。
- **上限测试**：盲标 c-dev 全量本身就是 Claude 零样本上限。注意写手与标注者同为 Claude，只说明“按这份规范，同一模型家族结论一致”。GLM 额度只剩 6 次，不用。
- 单句任务数据：r14 的 `train/runs/r14/dataset/{train,val,calib}.jsonl` 原样作为来源（18,824 条），与续接训练池一起按剧本 / 家族重新切分。
  r14 的五套锁定评测继续作为 `locked_eval`，永不进训练。

## 3. 配方

- **c1**：从 r14（`models/laya-smart-home/45f3dedb/torch`）初始化，r14 配方（22 层全解冻、batch 16、lr 2.5e-5 / 1e-4、brier 0.5、val NLL 选轮），2 epoch，`pad_multiple 64`，不加 `gold_weights`。
- **校准**：calib 同时含单句和续接两类题，按题型和选项数分档拟合（现有 `calibrate`，每档 ≥ 30 条）。分任务报告 T、ECE 和 0.9 下的覆盖。
  如果两类题在同一档里需要的温度明显不同（分别拟合后某一类 ECE 降 > 0.03），再在 Agent 适配器里按题重新调温：`p^(T0/T1)` 归一化与 `softmax(z/T1)` 完全等价，不改 laya 运行时和 NPU scorer。
- 一次只改一个变量；从基座联合训练（r14 配方原样）留作单句回退时的对照。

## 4. 指标

策略：top 为可执行选项且 `p ≥ τ_exec` → 执行；top 为 `取消` 且 `p ≥ τ_cancel` → 取消；其余 → 交还 LLM。每个快照恰好落入一类：

| 类别 | 金标 | 策略结果 | 代价 |
|---|---|---|---|
| 正确执行 | 可执行选项 X | 执行 X | — |
| **错误执行** | 其他任何金标 | 执行 | 设备做了用户没要的事 |
| 正确取消 | 取消 | 取消 | — |
| **错误取消** | 不是取消 | 取消 | 吞掉用户的请求 |
| 漏掉续接 | 可执行或取消 | 交还 LLM | 只多一次 LLM 延迟 |
| 正确交还 | 重新理解 | 交还 LLM | — |

- **接管率** = (正确执行 + 正确取消) / 金标为可执行或取消的快照；同时报告占全部快照的比例。
- 零观察错误不等于零风险：错误执行报告 n 与单侧 95% 上界（零错误时约 3/n）。
- 换序一致率：选项打乱后 argmax 与原顺序一致的比例。
- 单句回归：locked-182、v2-dev、v3-dev 上的配对门槛（`--baseline train/runs/r14/eval --alpha 0.05`），**外加** 0.9 下 control 自动执行的覆盖与精度（现有门槛只比准确率，会放过温度退化）。

## 5. 门槛（在 c-dev 上判，先登记后训练）

阈值在网格 {0.80, 0.85, 0.90, 0.95, 0.97, 0.99} 上取：`τ_exec` 取使 c-dev 错误执行为 0 的最小值，`τ_cancel` 取使错误取消 ≤ 1% 的最小值。取定后冻结，再跑一次 c-test。

1. 续接：c-dev 错误执行 0（报告自动执行 n 与上界），错误取消 ≤ 1%，接管率 ≥ 50%，换序一致 ≥ 95%。
2. 单句：三套开发集配对门槛通过；0.9 自动执行覆盖比 r14 降不超过 3 个百分点，精度降不超过 1 个百分点。
3. 两条都过 → 候选：跑 c-test 一次，报告全部类别与上界；随后才做 ONNX / RKNN 导出、torch 与 NPU 逐点一致、板上时延（沿用 800 ms 调用预算，续接输入按档位实测）。

## 6. 停止规则

1. 成功：门槛 1、2 都过 → 候选，按 §5.3 继续。
2. 续接不过：按 c-dev 误差分析定下一轮唯一改动（数据概念 / 配方），先登记。
3. 单句回退：下一轮改为从基座联合训练（r14 配方原样），对照是否为 r14 权重上继续训练造成。
4. 训练集探针：训练池续接准确率 < 95% → 表示或容量问题，不再加数据；学会了但 c-dev 不行 → 泛化问题。
5. 预算：最多 c4；每轮写手调用数在登记时写明。

### c2（登记，2026-09-29）

- **唯一改动（相对 c1）**：初始化从 r14 权重改为基座 `models/laya-multilingual/1c5edc17/torch`，r14 配方原样 3 epoch。数据集与 c1 完全相同

**c2 之后的判定（先定规则，再看结果）**

1. c2 过门槛 → 候选，按 `tools/gate_then_test.sh` 跑一次 c-test。
2. c2 不过，且仍有 c1 的样子（v2-dev“多个设备或整屋”正确率 ≤ 0.78，或 v3-dev“无关”正确率低于 r15 的 0.880）
   → 与初始化无关，是混入续接数据后的偏移 → **c3 改数据**：补单句的（a）多设备 / 整屋查询与控制、（b）提到设备的“无关”与同词“控制”对照，

3. c2 不过，但退步落在别的切片、样子像 r15 → 主要是种子波动；c3 仍补（a）——34 条的切片换种子就会翻，补厚它是有证据的；
   （b）不补。
4. 不论哪种，c3 过开发集门槛后，单句加跑一次从未参与挑选的 v2-test 与 accept 集，作为最后的回归检查。

**c2 结果（2026-09-29）**：不过门槛（13 条不过 5 条；c1 不过 2 条），c-test 未跑。报告在 `train/runs/c2/`。

- 单句：v2-dev 93.65%（配对不过）；0.9 覆盖 182 / v2 / v3 = 68.6 / 49.1 / 31.5（r14 72.1 / 64.9 / 40.7，**三套都不过**）。

  → 落到**第 3 条**：c3 补（a）多设备 / 整屋，不补（b）；初始化用门槛更好的 c1 路线（r14）。

### c3（登记，2026-09-29）

- **唯一改动（相对 c1）**：训练数据加入单句补充数据（a）：多设备 / 整屋的查询与控制，每条配一条用词相近的单台对照句

- 依据：c1 在 v2-dev device 上改错的 8 条里 4 条是“多个设备或整屋”（c1 特有，r15 / c2 都没有）；r14 训练集“查询 + 多个设备或整屋”只有 34 条。
  这 4 条不再翻时，配对检验为改错 4 / 改对 1（p ≈ 0.38）。另外 4 条改错属于种子波动，补数据治不了——c3 仍可能因波动卡在门槛上。
- 口径：查询里的“都 / 全部 / 所有 / 还有哪些开着”一律 `多个设备或整屋`（与现有 34 条和 v2 口径一致；单句 LABELING §3 的“同类少量写列表”
  与现有数据不一致，c3 数据按现有口径，不改共享规范）。
- 卫生：写手只拿概念描述、不读 `evals/`；写完用 `purge_training_overlap.py` 的同一规则只清理本目录；另一个模型盲标 20%，一致率 < 90% 先改说明。
- 规模：5 批 × 100 条（每批：多设备查询 45、单台查询对照 25、多设备控制 20、单台控制对照 10）。
- 判定：同 §5；过开发集门槛后单句加跑 v2-test 与 accept，标准同门槛 2（对 `train/runs/r14-reeval`：配对门槛通过、覆盖降 ≤ 3pt、
  精度降 ≤ 1pt），任何一条不过就**不跑 c-test**；都过再用冻结阈值跑 c-test。（更正：v2-test 当年参与过 r14 / r15 的比较，

### 单句“误执行”口径复核（2026-09-30，按 Agent 实际规则）

- **定义**：只有 Agent 真的会下发设备命令才叫“执行”——`LayaInterpreter._result` 给出控制 + 真实设备（不是“多个设备或整屋”“没有对应的设备”），
  且 `SmartHomeCommand._confident` 通过（intent_p ≥ 0.8；非无关再要 device_p；控制再要 action_p）。执行了但金标不是控制 = **误触发**；
  金标是控制但设备 / 动作不在金标里 = **错设备 / 错动作**。“没有对应的设备”（回“家里没有…”）、“多个设备或整屋”（弃权）、查询、判成无关、低置信都**不是执行**。

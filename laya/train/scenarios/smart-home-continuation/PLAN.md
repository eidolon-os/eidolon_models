每轮训练前先在本文件末尾登记（唯一改动、预期、判定），跑完再写结果，不看 c-test 调任何东西。

## 1. 目标与边界

- 同一个 laya 模型既答单句三题（intent / device / action，r14），又答两道续接题（`pick` / `follow`），**单句任务不回退**。
- Laya 只从 Agent 给的有限选项里选、取消（仅 `pick`），或交还 LLM。不保存历史，不产生新设备、新动作或数值，不调用设备。
- 本计划只产出 Models 侧的数据、权重、报告和状态格式（`continuation-laya-v1`）。**不改**生产模型清单、服务配置、Agent 代码和 participation 训练。
  Agent 接入（调用前置条件、状态拼装、影子评测）按 `LABELING.md` §1–2 另行实现。

  r14 的五套锁定评测继续作为 `locked_eval`，永不进训练。

## 3. 配方

- **c1**：从 r14（`models/laya-smart-home/45f3dedb/torch`）初始化，r14 配方（22 层全解冻、batch 16、lr 2.5e-5 / 1e-4、brier 0.5、val NLL 选轮），2 epoch，`pad_multiple 64`，不加 `gold_weights`。
- **校准**：calib 同时含单句和续接两类题，按题型和选项数分档拟合（现有 `calibrate`，每档 ≥ 30 条）。分任务报告 T、ECE 和 0.9 下的覆盖。
  如果两类题在同一档里需要的温度明显不同（分别拟合后某一类 ECE 降 > 0.03），再在 Agent 适配器里按题重新调温：`p^(T0/T1)` 归一化与 `softmax(z/T1)` 完全等价，不改 laya 运行时和 NPU scorer。
- 一次只改一个变量；从基座联合训练（r14 配方原样）留作单句回退时的对照。

## 4. 指标

策略：top 为可执行选项且 `p ≥ τ_exec` → 执行；top 为 `取消` 且 `p ≥ τ_cancel` → 取消；其余 → 交还 LLM。每个快照恰好落入一类：

| 类别 | 金标 | 策略结果 | 代价 |
|---|---|---|---|
| 正确执行 | 可执行选项 X | 执行 X | — |
| **错误执行** | 其他任何金标 | 执行 | 设备做了用户没要的事 |
| 正确取消 | 取消 | 取消 | — |
| **错误取消** | 不是取消 | 取消 | 吞掉用户的请求 |
| 漏掉续接 | 可执行或取消 | 交还 LLM | 只多一次 LLM 延迟 |
| 正确交还 | 重新理解 | 交还 LLM | — |

- **接管率** = (正确执行 + 正确取消) / 金标为可执行或取消的快照；同时报告占全部快照的比例。
- 零观察错误不等于零风险：错误执行报告 n 与单侧 95% 上界（零错误时约 3/n）。
- 换序一致率：选项打乱后 argmax 与原顺序一致的比例。
- 单句回归：locked-182、v2-dev、v3-dev 上的配对门槛（`--baseline train/runs/r14/eval --alpha 0.05`），**外加** 0.9 下 control 自动执行的覆盖与精度（现有门槛只比准确率，会放过温度退化）。

## 5. 门槛（在 c-dev 上判，先登记后训练）

阈值在网格 {0.80, 0.85, 0.90, 0.95, 0.97, 0.99} 上取：`τ_exec` 取使 c-dev 错误执行为 0 的最小值，`τ_cancel` 取使错误取消 ≤ 1% 的最小值。取定后冻结，再跑一次 c-test。

1. 续接：c-dev 错误执行 0（报告自动执行 n 与上界），错误取消 ≤ 1%，接管率 ≥ 50%，换序一致 ≥ 95%。
2. 单句：三套开发集配对门槛通过；0.9 自动执行覆盖比 r14 降不超过 3 个百分点，精度降不超过 1 个百分点。
3. 两条都过 → 候选：跑 c-test 一次，报告全部类别与上界；随后才做 ONNX / RKNN 导出、torch 与 NPU 逐点一致、板上时延（沿用 800 ms 调用预算，续接输入按档位实测）。

## 6. 停止规则

1. 成功：门槛 1、2 都过 → 候选，按 §5.3 继续。
2. 续接不过：按 c-dev 误差分析定下一轮唯一改动（数据概念 / 配方），先登记。
3. 单句回退：下一轮改为从基座联合训练（r14 配方原样），对照是否为 r14 权重上继续训练造成。
4. 训练集探针：训练池续接准确率 < 95% → 表示或容量问题，不再加数据；学会了但 c-dev 不行 → 泛化问题。
5. 预算：最多 c4；每轮写手调用数在登记时写明。

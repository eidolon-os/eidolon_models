# 写手指南：单句任务补充数据（c3 条件执行，PLAN.md §7“c2 之后的判定”）

只在 c2 不过门槛、且判定落到第 2 / 3 条时使用。目的：补厚 c1 里被测出退步、且训练数据薄的单句切片。
**先完整读 `train/data/LABELING.md`（单句三道题的规范）和 `train/data/README.md` 的 authored 格式**，严格按它们标。

## 1. 输出

`train/data/authored/smart-home-c3/<批>.jsonl`，一行一条，authored 格式（`train/data/README.md`）：

```json
{"home": "family3", "text": "家里的灯是不是都关了", "intent": "查询", "device": "多个设备或整屋", "tags": ["c3-multi-query"]}
```

- `home` 只能用本批指定的户型（`train/data/homes/smart-home/<名>.json`），设备名逐字取自该户型清单。
- `tags` 第一个是切片名（下表），后面可加你自己的细分标签。
- 写完跑 `gen` 校验（见 `train/data/README.md`“校验”一节，把路径换成本目录），任何金标不是合法选项都要改。

## 2. 切片（每批的条数写在任务里）

| 切片（tag） | 写什么 | 金标要点（LABELING §3、§8） |
|---|---|---|
| `c3-multi-query` | 问多台 / 整屋 / 某一类全部设备的状态：“灯都关了吗”“楼上还有什么开着”“两台空调都关了没”“家里现在几台设备在运行” | 查询 + `多个设备或整屋`；只问一台的对照句（“客厅灯关了吗”）→ 那一台 |
| `c3-multi-control` | 让多台 / 整屋 / 某一类全部设备一起动：“把楼下的灯都关了”“所有空调调到 26 度”“两个卧室的空调都开” | 控制 + `多个设备或整屋` + 动作；“除了 X 其他都关”剩一台时标那一台 |
| `c3-mention-noncommand` | 句子里有设备名和动作词，但**不是对助手的请求**：对家人 / 孩子 / 宠物说话、讲故事、说计划、转述别人的话、陈述已做的事 | 无关（LABELING §2 表、§7、§8） |
| `c3-mention-control` | 与上一类**用同样的设备词**、但确实是对助手的请求（可以带家常语气、先闲聊再下指令） | 控制 + 设备 + 动作 |

- **对照要成对**：同一户型里，一条“无关”配一条用词相近的“控制”；一条多设备查询配一条单台查询。对照句也计入各自切片。
- 句子要像真人在家说的话：口语、长短不一、可以带语气词、偶尔有 ASR 式的小错字。

## 3. 卫生

- **不读** `evals/` 下的任何文件，也不读 `train/runs/`。只按上面的概念描述写。
- 同一批不要重复句式；不同批次之间也尽量换说法。
- 写完后由另一位标注者盲标 20%，一致率 < 90% 先改规范再用。

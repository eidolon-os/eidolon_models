## 1. 输出

`train/data/authored/smart-home-c3/<批>.jsonl`，一行一条，authored 格式（`train/data/README.md`）：

```json
{"home": "family3", "text": "儿童房跟主卧的窗帘拉上没有", "intent": "查询", "device": "多个设备或整屋", "tags": ["c3-multi-query"]}
```

- `home` 只能用本批指定的户型（`train/data/homes/smart-home/<名>.json`），设备名逐字取自该户型清单。
- `tags` 第一个是切片名（下表），后面可加你自己的细分标签。
- 写完在 `laya/` 下跑 `.venv/bin/python train/scenarios/smart-home-continuation/tools/check_single.py <你的文件>`，报错就改到通过。

## 2. 切片（每批的条数写在任务里）

| 切片（tag） | 写什么 | 金标要点（LABELING §3、§8） |
|---|---|---|
| `c3-multi-query` | 问多台 / 整屋 / 某一类全部设备的状态、读数或进度（说法自己想，覆盖“都 / 全 / 所有 / 还有哪些 / 几台 / 哪几个”、按楼层或区域、跨品类） | 查询 + `多个设备或整屋`；只问一台的对照句 → 那一台（查询） |
| `c3-multi-control` | 让多台 / 整屋 / 某一类全部设备一起动（按楼层、按区域、按品类、“两个 / 三个都”） | 控制 + `多个设备或整屋` + 动作；只动一台的对照句 → 那一台；“除了 X 其他都关”剩一台时标那一台 |
| `c3-mention-noncommand` | 句子里有设备名和动作词，但**不是对助手的请求**：对家人 / 孩子 / 宠物说话、讲故事、说计划、转述别人的话、陈述已做的事 | 无关（LABELING §2 表、§7、§8） |
| `c3-mention-control` | 与上一类**用同样的设备词**、但确实是对助手的请求（可以带家常语气、先闲聊再下指令） | 控制 + 设备 + 动作 |

- **对照要成对**：一条多设备句配一条用词相近的单台句（tag 仍用本切片名，再加 `single-contrast`）。
- **口径**：查询里的“都 / 全部 / 所有 / 还有哪些开着 / 几台”一律 `多个设备或整屋`，不写设备列表（与现有训练数据和 v2 一致；
  单句 LABELING §3“同类少量写列表”这一句在查询上与现有数据不一致，c3 按现有数据口径）。只有一台符合时（户型里只有一盏灯）→ 那一台。
- c4 的两个切片：**每条“无关”配一条“控制”**，两句用同样或几乎同样的设备词和动作词，区别只在“是不是对助手的请求”
  （说话对象、时态、转述 / 计划 / 陈述 / 讲故事 vs 现在让助手做）。无关句不填 device / action；控制句按 LABELING 填设备与动作。
  覆盖：对家人 / 孩子 / 宠物说的祈使句、讲故事或童谣里的开关灯、将来的计划与条件、转述别人（物业 / 房东 / 外卖员）的要求、
  陈述自己已经做了、常识 / 能力 / 规格说明、线上会议或打电话时对别人说的“开一下 / 大点声”。
- 句子要像真人在家说的话：口语、长短不一、可以带语气词、偶尔有 ASR 式的小错字。

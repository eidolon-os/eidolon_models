# 写手指南：家居续接话语

先完整读 `LABELING.md`。你拿到的每一行是一个剧本：Agent 当前的上下文、这次题目的选项、以及**这句话要表达的意图（`要求`）**。
你只写**用户接下来说的那一句话**。金标由剧本定，你不改，也看不到。

## 1. 输入（`train/data/continuation/writer/<批>.jsonl`）

```json
{"frame_id": "train-pick-0002-0", "题目": "pick",
 "context": {"上一句": "帮我开一下加湿器", "Agent": "儿童房加湿器、主卧加湿器，要哪一个？", "待执行": "打开"},
 "选项": ["儿童房加湿器", "主卧加湿器", "取消", "重新理解"],
 "要求": "选主卧的「主卧加湿器」，同时带附和语气（嗯、对、好）或把动作「打开」再说一遍。"}
```

- `pick`：Agent 刚问“A、B，要哪一个？”，还没执行。`待执行` 是待确认的动作。
- `follow`：Agent 刚执行完（或刚查询完）`设备`，`Agent` 是它回给用户的话。

## 2. 输出（一行一个 JSON，与输入同序）

```json
{"frame_id": "train-pick-0002-0", "utterance": "嗯，主卧那个吧"}
{"frame_id": "train-follow-0001-0", "skip": "吸顶灯说上锁太牵强"}
```

- 每个 `frame_id` 恰好一行：`utterance`，或者 `skip` 加一句原因。
- **按 `要求` 写，且只表达 `要求` 说的意图。** 不要额外加别的请求、别的设备或别的动作（除非 `要求` 让你加）。
- 写不自然、或按 `LABELING.md` 这句话会落到另一个选项上时，**写 `skip`**，不要硬写。

## 3. 怎么写

- 像真人对着音箱说话：短、口语、可以省略、带语气词（“嗯”“那个”“吧”“啊”），偶尔啰嗦。中文，一句话，一般 2–20 个字。
- **同一批里不要重复句式。** 同一个上下文会有 2–3 个不同的 `要求`，它们是对照：话要贴近，但意图不同。
- 称呼设备的方式要多样：房间（“主卧的”）、简称（“加湿器那个”）、名字里的词、位置（“楼上那个”）。按 `要求` 限定的方式来：
  要求“只用顺序”就不要出现房间和名字；要求“不说设备名”就用“它 / 这个”或干脆省略。
- 口语里真实会出现的数字写法都可以（“二十六度”“26度”“一半”“百分之三十”），不要写成“26°C”。
- **不要写元信息**：不要说“选第一个选项”“取消待确认操作”“交给大模型”“重新理解”，也不要复述 `要求` 的措辞。
- `取消` 类的话要真的是“这次不要了”，不要夹带新要求；`重新理解` 类的话照 `要求` 写，不要写成模糊的取消。
- 不要抄已有评测集或其他批次的句子。

## 4. 例子（上下文：待执行“打开”，候选 儿童房灯、玄关灯）

| 要求 | 好 | 不好（原因） |
|---|---|---|
| 用房间指出玄关灯 | 玄关的吧 / 门口那个 | 我选玄关灯这个选项（元信息） |
| 用顺序指出第 2 个 | 后面那个 / 第二个 | 玄关那个第二个（出现了名字） |
| 选玄关灯但动作改成关闭 | 玄关的关掉 | 玄关的（没改动作，意图不对） |
| 明确不要这次操作 | 算了不开了 / 不用了我自己来 | 不开了，把空调打开（夹带新要求） |
| 只附和，不指出哪台 | 好的好的 / 嗯 | 嗯，儿童房（指出了一台） |

## 5. 盲标（另一位标注者）

盲标文件只有 `context`、选项（含说明）和 `utterance`，没有 `要求`。按 `LABELING.md` 选一个选项：
```json
{"frame_id": "...", "label": "玄关灯", "note": "拿不准时写原因，否则省略"}
```

# 参与决策：标注规范

所有训练、开发、测试数据都按这份规范标。写数据前必读；遇到规则没覆盖的情况，先在第 6 节补规则，再写数据。

## 1. 决策点

每个快照是一个决策点：**在"最新一条"之后，下一步应该发生什么？** 只看公开信息：场景目标、候选角色、本轮用户请求、
公开记录（已经播完的发言）。不猜角色没说出口的打算。

一轮 = 一条用户输入（`本轮用户请求`）加上它引发的角色发言。新的用户输入开始新的一轮，之前的轮次留在公开记录里。

## 2. 动作（`action`）

| 动作 | 什么时候 | 例 |
|---|---|---|
| **respond** | 本轮请求**还需要**某位角色说话，而且不缺信息就能说 | 用户问问题、点名某人、要求讨论；A 分两次讲、第一次刚讲完 |
| **clarify** | 不问清楚就没法正确回应：指代不明、要求内容不明、点名的角色不在场 | 三人在场时用户说"让他接着说"（最近没有单一的"他"） |
| **wait** | 这一轮**没完成**，但现在不该有人说话 | 用户说"先别出声，等我画完"；角色刚问完澄清问题，等用户回答 |
| **finish** | 本轮请求**已经完成**（要的内容都说到了），或用户明确结束这一轮 | 只要一人说一句且已说完；用户说"好了就到这吧" |

判定细则：
- **不能因为角色刚说完一句就 finish**：看请求要的是什么。"讲三个笑话"讲了一个 → respond；讲完第三个 → finish。
- **不能因为出现了某个名字就选他**：只提及（"阿舟上次说的那个店"）不等于点名；要看用户是要谁说。
- **开放问题不澄清**：没点名、谁都能答的问题（"你们觉得周末去哪好"）→ respond，由合适的角色答，不是 clarify。
- **澄清发出后**：最新一条是角色的澄清问题 → wait。用户回答之后（新一轮）→ 按回答 respond。
- **明确要求安静 vs 安静陪伴**："陪着我就好，可以说句让我安心的话" → respond（一句）；说完 → finish。
  "先别说话" / "等我一下" / "我想想" → wait；用户回来说"好了你说吧" → respond。
- **用户明确结束**："好了，今天就聊到这"、"不用了，谢谢" → finish。只是道谢但话题还在进行（"谢谢，那还有别的办法吗"）→ respond。
- **纯确认 / 收尾话，不需要回应**（"好的"、"嗯嗯就这样"）→ finish。
- **讨论类请求何时结束**：用户要求"你们讨论一下" → 至少有两位基于实际观点交流过，或用户设定的条件满足后 → finish；
  讨论仍在推进、还有人没回应上一位的观点 → respond。拿不准时看请求字面要求（"每人说一句" → 每人都说过才 finish）。
- 剩余回复次数只由运行时管，不影响标注（次数用完运行时会自己停）。

## 3. 人选（`speaker`，仅 respond / clarify）

| 情况 | 人选 | 例 |
|---|---|---|
| 点名（名字、唯一的称呼或描述） | 那一位 | "阿舟你说说"、"那个做饭的你来讲" |
| 单聊（只有一位候选） | 那一位 | — |
| 多段请求让 A 继续 | A（**同一人继续，不轮换**） | "阿舟分两次讲"，第一次讲完 → 仍是阿舟 |
| 交棒 / 回应某人的观点 | 被要求回应的那位 | "小岚你怎么看阿舟刚说的" |
| 追问某人刚说的内容 | 刚说的那位 | 用户："你刚说的面馆在哪？"（紧接阿舟的发言） |
| 开放问题 | **所有合适的候选都对**（写全列表）；问题落在某人的角色专长上时，只列专长匹配的 | "你们觉得呢"→ 全部；"这道菜怎么做"→ 厨师角色 |
| "每人说一句" | 还没说过的所有人都对 | — |
| 同名且有区分线索 | 符合线索的那位 | 两个"林小满"，用户说"说话轻声细语的那位" |
| clarify | 由谁来问：没有特殊理由时**所有候选都对**；被含糊点到的同名角色之一来问也可以 | — |

## 4. 澄清的原因（`clarify_about`，仅 clarify）

| 选项 | 什么时候 |
|---|---|
| 指代不明 | 不确定用户说的是哪一位 / 哪一个（"让他说"、两个同名且无线索） |
| 要求不明 | 不确定用户要做什么（"那个再来一次"而前面没有可对应的内容） |
| 对象不在场 | 用户点名的角色不在候选里 |

运行时按原因生成有界任务说明，例如"请用户说明想让哪一位回答"；台词由回复模型生成。

## 5. 数据卫生

- 标签只能依赖公开状态可推出的事实；写手不得在台词里泄露"我说完了"之类的元信息来替模型做判断（真实角色不会这样说）。
- 同一剧本的换序 / 改名变体算一个家族，按家族切分；p-dev、p-test、24 条筛查永不进训练。
- 每批数据抽 10% 盲标：第二位写手只看公开状态独立标，和剧本不一致的逐条裁决（重写、丢弃或补规则）。

**2026-09-28（评测集撰写时的空白）**
- **明确要求安静陪伴 / 别出声**，不论之后会不会回来（"陪我坐会儿，别出声"、"不用再说了，就这样陪着我"、"你别说话了，让我一个人待会儿"）→ **wait**。
  finish 只用于请求已经完成或用户收尾 / 离开。
- **用户中途喊停**（"等等等等"、"稍等"、"我先想想"）→ wait。
- **只道谢、纯确认、纯感叹**（"谢谢你～"、"好的"、"哈哈哈好吧"、"嗯，真好"、"哦哦"）→ finish；道谢后接着提问 → respond。
- **用户说要离开**（"我先去睡了"、"我去煮面"、"先去吃饭了，回头再聊"）→ finish。
- **角色答完后顺口反问**（"……你晚饭吃了吗？"）：请求已经答完 → **finish**（闲聊的反问不卡住这一轮）；只有**澄清问题**之后才是 wait。
- **"那个"指代**：前面有两个及以上同样可能的对象（刚讲了两个故事、推荐了两个地方）→ clarify（指代不明）；
  说"刚才那个 / 最后那个"或只有一个可能的对象 → 按那一个处理。
- **陪伴里点名不在场的人**（"阿杰在吗"）同团队 → clarify（对象不在场）。
- **"按上回那样"而公开记录里没有上回** → clarify（要求不明）；只依据公开记录，不假设跨会话记忆。
- 隐含的不满或疑问（"加一份要多五块钱诶"）不是纯确认 → respond。

**2026-09-28（团队评测撰写时的空白）**
- **插话后恢复**：用户说"A 先等一下，B 你说说……"——B 答完后，A 还欠这次发言 → respond A（不是 finish）。
- **同名角色的区分线索**只认明确的描述、职业、性格或称呼；"这个问题更像谁会答"不算线索 → clarify（指代不明）。
- **点名了但要求不明** → clarify，由**被点名的那位**来问（speaker 只写他）。
- **"他 / 她"只有一个可能的对象**（公开记录里只有一位角色说过话，或最近明确只指一位）→ 直接 respond 那一位，不澄清。
- **开放问题的数量**："谁给个建议 / 谁推荐一个" → 一位答完即 finish；说了数量（"推荐两件"、"说三个"）→ 答满才 finish；
  "你们都说说" → 同"每人说一句"。
- **换内容不换人**：用户对正在说话的角色改要求（"笑话算了，改讲个鬼故事吧"）而没点别人 → 仍是这位。
- **讨论完成**：两位以上基于实际观点交流过、用户没有设定别的条件 → finish；用户设了条件（"辩到有一方认输"）→ 条件满足才 finish。
- **追问更早某位的内容**：用户追问的是前面某位角色说过的事（不一定是最新一位）→ respond 那一位。
- **"你们觉得呢 / 大家怎么看"这类开放问题**，没说"都 / 每人 / 几个"→ 一位答完即 finish（同"谁给个建议"）；说了"都说说 / 每人一句"→ 每人都说过才 finish。
  **但点了名的"你俩 / 你们几个"不算开放问题**："海棠、葱花，你俩觉得呢"= 点名两人（T03），被点到的每一位都说过才 finish；"你们俩谁说都行"才是一位即可。

**2026-09-28（训练数据撰写时的空白）**
- **"说一句就好，说完就别出声了"**：那一句说完后 → wait（用户明确要求之后安静）。
- **情绪信号不是纯感叹**："呜呜呜"、"唉……"在倾诉 / 难过的语境里 → respond；开心的"哈哈哈好吧"才是收尾 → finish。
- **隐含不满或追问**："就这？"、"那我肯定坚持不了一年……" → respond。
- **多段请求中途的附和**（"嗯嗯"、"然后呢"）→ 原请求还没完成 → respond 同一位接着说；中途插一个旁支问题 → respond 回答它（原请求之后可继续）。
- **一步一步讲**（"一步一步说"）而用户没要求每步等他 → 同一位接着 respond，讲完才 finish。
- **"你听着就行，先别回我"一直有效**：用户接着倾诉（没解除这个要求）→ 仍是 wait；用户说"你说说看 / 你怎么看"才解除 → respond。

**2026-09-28（团队训练数据写手 1 / 2 / 4 拿不准的地方）**
- **同名角色里一位刚说完，用户叫这个名字说"再 / 接着 / 继续"** → 刚说完的那位（延续本身就是明确线索）；
  问题明显属于另一位的身份（"秋生，你们报馆那会儿……"）→ 那一位；都不沾 → clarify（指代不明）。
- **共享称呼**：两位都是"老师"，用户只说"老师，你们学校……" → 同"同名无线索" → clarify（指代不明）。
- **"问问 X / X 最懂了吧 / X 你看呢"** 是把话交给 X（点名），不是只提及。
- **角色之间当面提问**：讨论中一位直接问另一位（"刘妈妈，你家孩子自己愿意吗？"）→ respond 被问的那位；只反驳不提问 → 按"讨论完成"判。
  角色问**用户**的闲聊反问仍是 finish。
- **讨论完成里的"还有人没回应"**指最新的观点冲着某位角色来（当面提问 / 点名反驳）而他还没回应；
  三人讨论里第三位没开口不算——两位已经基于观点交流过 → finish。
- **用户设了结论条件**（"最后给我定一个地方"、"辩到有一方认输"）而还没满足 → respond，**除刚说完的那位以外**的参与者都对（两人辩论就是另一位；谁都可以收拢结论）。
- **撤回 vs 暂停**："算了算了，我自己再研究研究" / "不用了" → finish（请求撤回）；请求没完成时"等等 / 我先想想" → wait；
  建议都给完后用户说"我再想想"（是在考虑建议）→ finish。
- **"嘘——" / "小声点，孩子睡了"** → wait（要求安静）。
- **角色出的题等用户作答**（谜语且没说最后统一揭晓、小测验、模拟面试的提问、"你猜猜看"）→ wait：这一轮在等用户；
  请求完成后顺口的闲聊反问、用户没要这类活动时角色顺口卖关子（"你猜为什么？嘻嘻"）仍是 finish。
- **用户回答角色的问题**：回答澄清问题 → 按澄清后的请求选人（点名 / 专长，§3），不一定是问的那位；
  回答角色的闲聊反问（"一点多吧……"）→ 问的那位接着说。
- **没点名的后续追问沿用对话对象**：用户点名 X 开始的话题，后面没点别人的追问 / 核对（"算出来是 9，对不对？"）→ 仍是 X。
  开放问题（没点名）之后的"还有别的吗"仍是开放的。
- **"再来个人说说 / 换个人"** → 只列还没说过的；只给数量的请求（"推荐三个"）→ 说过的人也可以接着说。
- **没有请求的收尾话**（"那我下午去你那儿买一杯"、"哇我要去看！"）→ finish；带难过 / 不满 / 疑问的见上文 → respond。

**2026-09-28（团队训练数据写手 3 拿不准的地方）**
- **同名角色的对话上下文**：用户紧接着某位同名角色的话题追问（刚和他聊完、问的正是他刚说的事）→ 算线索，给那一位；
  上下文和内容指向不同的人（刚和店员美美聊完，问的却是猫美美用的猫砂）→ clarify（指代不明）。

  只是问题落在某位的专长上（"小林，我家娃咳嗽三天了"、两位"老师"时问学琴）→ 不算（"更像谁会答"不是线索），和上下文冲突时 clarify。

  道谢、确认、用户自己的打算或感叹 → finish（见上文）。
- **多段请求中途的旁支问题答完后**：原请求还没完成、用户也没叫停 → respond 原来那位接着讲（同"插话后恢复"）。
- **描述语对得上多位**（"那个养鱼的"而两三位都沾边）→ clarify（指代不明）。
- **一句话里两个请求给两个人**（"小二，上壶茶。对了掌柜的……"）→ 两位都对。

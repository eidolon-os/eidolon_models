## 训练数据

- GLM（`glm_generate.py`，剧本定金标、GLM 写文字）：试点 10 次调用（一次 2 个 vs 3 个的对比，修掉 texts 格式、昵称点名、剧本措辞泄露标签三个问题）；
  正式计划 1,650 个剧本（seed 2），3 个进程并行、每次 3 个，通过率约 90%。
- Claude：8 位写手（团队 4、陪伴 4），各 70 个 episode，共 560 个 episode、3,050 个决策点；侧重对照对、长对话、有场景目标、边界难例、口语零碎。
  写手报告的拿不准处逐条裁决进 LABELING §6，按新裁决改了 3 处金标（CT1-0031#3、CT2-0015#3、CC1-0037#3）。
- **盲标抽检**：每个 episode 只抽一个快照（避免同 episode 前缀泄露）、打乱，GLM 300 + Claude 100，两个独立 Claude 标注者只看 LABELING.md 和快照。
  动作一致 **97.5%**（GLM 96.7%、Claude 100%），人选 204/204。GLM 的分歧指向几类系统性的"剧本定的金标和 GLM 写出的台词对不上"：
  用户说"别说话"却按剧本让角色回应（6 条）、剧本要"指代不明"但台词写了"刚才那位 / 你们谁"（10 条）、用户台词写成角色口吻（2 条）；
  还有一类是规范空白——角色问用户要信息（"你想学哪一样？"）后该 wait 还是 finish（补了裁决）。
  修正放在 `train/data/participation/fixes.jsonl`（丢弃 / 改金标并截断），由 `build.py` 在建记录时应用，原始 episode 文件不改。
  全量扫描后共 64 条：角色问用户要信息 → wait 29 条（从 332 句"角色问句后 finish"里由两个 Claude 分类员按新裁决挑出）、
  "刚才那位 / 哪位都行"误标指代不明 13 条、要求安静却让角色回应 6 条、丢弃 16 个 episode（身份写反 3、台词按候选顺序写导致人设错位 13）。
  人设错位只用字面重合启发式抓了明显的，可能还有漏网；它不改"谁说过"的金标，只让公开记录的内容和人设对不上。
- **冒烟（p0-smoke）**：只用当时的 542 个 GLM episode、1 epoch，验证流水线与指标工具。同分布验证集动作 92.3%；p-dev 动作 80.9%、端到端 78.1%、
  应停却发言 13.8%、换序一致 98.9%（`train/runs/p0-smoke/eval/metrics.json`）。能学，p1 用全部数据、3 epoch。
  p-dev 上 wait→finish 的错里有一半是角色的澄清问题之后——和 GLM 数据里"角色问用户 → finish"的大量样本互相干扰，正是上面补的裁决。

## p1（登记）

- **假设**：之前 laya（v6–v8）和 JevK5 的失败来自数据太少（150 个快照）、可训练容量太小（最后 8 层 / 最后一个注意力块）、五种决策压成一道题且把"不确定"当类别训练。
  用 1,816 个 episode（Claude 560 + GLM 1,256；约 7,600 个决策点、每个 2 种候选排列，共 15,168 条记录）、拆成 action / speaker / clarify_about 三道题、abstain 交给运行时、
  全部 22 层解冻（家居 r14 配方），laya 能学会参与决策。
- **唯一改动**（相对之前的 laya IP 实验）：本路线的新任务定义与数据；配方用家居 r14 的固定配方。
- **预期**：p-dev 动作 ≥ 90%、端到端 ≥ 85%、应停却发言 ≤ 5%、换序一致 ≥ 95%。训练集探针（从训练集留出的同分布验证集）动作 ≥ 95%，
  否则判为学不会（容量 / 表示问题）而不是泛化问题。
- **过程**：首跑第 1 个 epoch 97 分钟未完成——精确长度补齐让 MPS 为每种形状编译一张图，内存到 32 GB 开始换页；停掉，加 `pad_multiple: 64`
  （预测逐位不变，最大概率差 0）和 `log_every` 后重跑。训练进程仍占约 29 GB（全部解冻 + Adam + 长序列激活），和其他应用一起换页，后半程 5–7 秒/batch。

  | epoch | 验证 acc（题目级） | 验证 NLL | 训练 loss |
  |---|---|---|---|
  | 1 | 94.5% | **0.250** | 0.421 |
  | 2 | 96.7% | 0.274 | 0.128 |

  第 2 轮 NLL 变差，按 NLL 选轮只保存了第 1 轮；第 3 轮跑到 400/1150 时经用户同意按 patience=1 早停（只有第 3 轮 NLL 反而低于 0.250 才会改变结论）。
  校准 T = 1.60（3–5 选项桶），校准集 NLL 0.261 → 0.224。包 `models/laya-participation/c46c818c`。
- **结果（p-dev，1,246 条 = 623 个决策点 × 2 种候选排列）**：

  | 指标 | p1 | 预期 | 冒烟 p0 |
  |---|---|---|---|
  | 动作 | **93.1%** | ≥ 90% ✓ | 80.9% |
  | 端到端 | **92.0%** | ≥ 85% ✓ | 78.1% |
  | 应停却发言 | **3.4%** | ≤ 5% ✓ | 13.8% |
  | 换序一致 | **99.7%** | ≥ 95% ✓ | 98.9% |
  | 人选（动作对时） | 97.4% | — | 93.6% |
  | 该说却沉默 | 7.4% | — | 11.2% |
  | 整个 episode 全对 | 69.2% | — | 29.2% |

  陪伴 94.3% / 团队 92.2%（端到端 94.3% / 90.2%）。GLM 零样本上限 95.8%（动作）。
  **训练集探针**（同分布验证集 1,598 条，按 episode 分组留出）：动作 93.2%——**低于登记的 95%**，但和 p-dev（93.1%）几乎一样，
  **没有泛化差距**；第 2 轮题目级验证 acc 已到 96.7%，所以不是"学不会"，是按 NLL 选在了欠拟合的第 1 轮。
- **错误（p-dev variant 0，51 条）**：
  - respond → finish 23：多段 / 计数请求没做完就停——"讲两个奇案"讲完一个、"说三个"说完两个、"你俩都说说"说完一位、辩论没到"认输"。
    角色触发的该说却沉默 41.7%，是最大的一块。
  - finish → respond 9：用户收尾 / 撤回没认出来——"不想聊了，晚安"、"算了不用了"、"第三个不用说了"、"我再纠结纠结"、"妈呀后背发凉"。
  - clarify → respond 7：两件里"有一个 / 那个"、同名无线索、点名不在场的人。
  - 其余人选 8、wait 3。
- **结论**：四项 p-dev 预期全部达到，路线成立（旧 laya v6–v8 / JevK5 在同类任务上远达不到）。瓶颈是拟合程度而非泛化：下一步不加数据，先改选轮。

## p2（登记）

- **假设**：p1 欠拟合（探针 93.2%，第 2 轮题目级 96.7%），按验证 NLL 选轮挑中了第 1 轮；NLL 变差只是置信度过高，温度校准能修。
- **唯一改动**：`checkpoint_metric: accuracy`（按验证准确率选轮，其余 p1 配方不变）。
  另有一处不改数学的运行改动：`batch_size 8 × grad_accum 2`（等效 batch 仍为 16，优化步数不变），把训练内存从约 29 GB 降下来、不再换页。
- **预期**：选中第 2 或第 3 轮；探针动作 ≥ 95%；p-dev 动作 ≥ 94.5%、端到端 ≥ 93.5%、应停却发言 ≤ 3.4%（不高于 p1）、校准后 ECE ≤ 0.05。
  respond → finish 类错误减少一半以上。若 p-dev 不升而探针升 → 开始出现泛化差距，p3 转向数据（计数 / 收尾类）。
- **过程**：batch 8 × 累积 2 后训练进程约 21.5 GB，不再换页，全程约 1.2 秒 / batch（8 条），3 个 epoch 共 2.3 小时。

  | epoch | 验证 acc（题目级） | 验证 NLL |
  |---|---|---|
  | 1 | 95.1% | 0.255 |
  | 2 | 96.8% | 0.238 |
  | 3 | **97.2%** | 0.312 |

  按准确率选中第 3 轮；校准 T = 2.86（3–5 选项桶），校准集 NLL 0.321 → 0.181（p1 为 0.224）。包 `models/laya-participation/d30c01c5`。
- **结果**：

  | 指标 | p2 | 预期 | p1 |
  |---|---|---|---|
  | p-dev 动作 | 94.1% | ≥ 94.5% ✗ | 93.1% |
  | p-dev 端到端 | 92.9% | ≥ 93.5% ✗ | 92.0% |
  | 应停却发言 | 3.4% | ≤ 3.4% ✓ | 3.4% |
  | 校准后 ECE（题目级） | 0.043 | ≤ 0.05 ✓ | 0.040 |
  | 换序一致 | 99.7% | — | 99.7% |
  | respond → finish（variant 0） | 21 | ≤ 11 ✗ | 23 |
  | **探针动作**（同分布验证集） | **96.3%** | ≥ 95% ✓ | 93.2% |

  陪伴 95.1% / 团队 93.3%。p-dev 错误 45 个（p1 51）：修好 22、新错 16、两轮都错 29，类别不变（多段 / 计数没做完就停 21、收尾当请求 10、人选 7、该澄清没澄清 5），
  新错里有暂停后"继续 / 记好了，继续"没接上。
- **结论**：选轮修好了欠拟合（探针 93.2 → 96.3），但 p-dev 只涨 1 个点——**第一次出现 2.2 个点的泛化差距**。按登记的分支，p3 转向数据。p2 成为当前最好的模型。

## p3（登记）

- **假设**：剩下的 p-dev 错误是概念层面的（多段 / 计数进度、收尾 vs 暂停后继续、澄清边界、讨论进度），现有数据覆盖不够密；
  按这些**概念**（不看 p-dev 原文）写的对照数据能迁移过去（家居 r9 的教训：概念级数据迁移，照抄样例不迁移）。
- **唯一改动**：训练数据加入 `claude-p3-{1..4}.jsonl`（240 个 episode、1,583 个决策点，约 +20%）及随之的裁决修正（讨论人选 11 处、同名冲突 2 条 fixes）。配方同 p2。
- **预期**：p-dev 动作 ≥ 95.0%、端到端 ≥ 94.0%、应停却发言 ≤ 3.4%、respond → finish ≤ 15；探针仍 ≥ 96%。
  若 p-dev ≤ 94.3%（不涨）→ 概念数据没迁移，p4 换杠杆（如针对"角色刚说完"这一类决策的损失权重 / 类别先验）。
- **过程**：训练集 14,394 条（p2 11,918），同 p2 配方，约 2.8 小时。

  | epoch | 验证 acc（题目级） | 验证 NLL |
  |---|---|---|
  | 1 | 94.6% | 0.263 |
  | 2 | 95.9% | 0.288 |
  | 3 | **96.1%** | 0.325 |

  （验证集含新数据的难例，与 p2 不可直接比。）选第 3 轮；校准 T = 2.56，校准集 NLL 0.314 → 0.191。包 `models/laya-participation/a1dde064`。
- **结果**：

  | 指标 | p3 | 预期 | p2 |
  |---|---|---|---|
  | p-dev 动作 | 94.7% | ≥ 95.0% ✗ | 94.1% |
  | p-dev 端到端 | 94.0% | ≥ 94.0% ✓ | 92.9% |
  | 应停却发言 | 2.5% | ≤ 3.4% ✓ | 3.4% |
  | respond → finish（variant 0） | 15 | ≤ 15 ✓ | 21 |
  | 换序一致 | 100% | — | 99.7% |
  | 探针动作（与 p2 相同的验证子集 1,598 条） | 96.2% | ≥ 96% ✓ | 96.3% |
  | 探针动作（p3 新数据留出的 396 条） | 89.6% | — | — |

  p-dev 错误 38 个（p2 45）：修好 23、新错 16、两轮都错 22；配对差异 23 vs 16，**统计上不显著**（McNemar p ≈ 0.26），
  但针对的两类都降了：没做完就停 21 → 15、收尾当请求 10 → 6。按动作置信度门槛（p-dev）：

  | 门槛 | 覆盖 | 动作 | 端到端 | 应停却发言 |
  |---|---|---|---|---|
  | 0.90 | 94.7% | 96.7% | 95.9% | 1.3% |
  | 0.95 | 87.9% | 98.2% | 97.5% | 0.9% |
  | 0.97 | 77.4% | 99.6% | 98.9% | 0.4% |

  （p2 在 0.95：覆盖 85.7%、动作 97.7%、端到端 96.5%。）
- **结论**：概念数据部分迁移，p3 成为当前最好的模型。剩下的高置信度错误集中在训练数据里少见的说法：
  没说数量的故事 / 讲解分几段说（台词以"……"结尾、情节没完）、多段请求中途暂停后"记好了，继续 / 回来了，你接着讲"、
  "你俩聊聊"里一位当面问另一位、"A 先等一下，B 你说"之后 A 恢复。新数据留出集只有 89.6%，概念还没学满。

## p4（登记）

- **假设**：概念没学满（留出 89.6%），且上面几种说法在训练数据里太少；再加一批按这些概念写的对照数据，p-dev 继续涨。
- **唯一改动**：训练数据再加 240 个 Claude episode（`claude-p4-*.jsonl`）：分段叙述的完成判断、暂停后的继续、两人对谈里的当面提问与恢复、同名线索。配方同 p2 / p3。
- **预期**：p-dev 动作 ≥ 95.3%、端到端 ≥ 94.5%、respond → finish ≤ 10、应停却发言 ≤ 3.0%；p3 新数据留出集 ≥ 92%。
- **停止条件**：若 p-dev 动作 ≤ 94.9%（不涨），判为这个基座上概念数据已饱和，停止加数据；p5 只做候选选定、阈值和一次 p-test。
- **过程**：训练集 16,946 条，同 p2 配方，约 3.3 小时。

  | epoch | 验证 acc（题目级） | 验证 NLL |
  |---|---|---|
  | 1 | 94.4% | 0.268 |
  | 2 | 95.9% | 0.305 |
  | 3 | **96.4%** | 0.342 |

  选第 3 轮；校准 T = 2.65，校准集 NLL 0.284 → 0.172。包 `models/laya-participation/ae6718a4`。
- **结果（p-dev）**：

  | 指标 | p4 | 预期 | p3 |
  |---|---|---|---|
  | 动作 | **97.4%** | ≥ 95.3% ✓ | 94.7% |
  | 端到端 | **96.6%** | ≥ 94.5% ✓ | 94.0% |
  | 应停却发言 | **1.1%** | ≤ 3.0% ✓ | 2.5% |
  | respond → finish（variant 0） | 7 | ≤ 10 ✓ | 15 |
  | 换序一致 | 99.7% | — | 100% |
  | 整个 episode 全对 | 84.2% | — | 71.7% |

  p-dev 错误 21 个（p3 38）：修好 26、新错 9，**配对差异显著**（McNemar p ≈ 0.004）。超过 GLM 零样本上限（95.8%）。
  **注意**：p4 的数据是看过 p-dev 的错误类别后写的（写手只拿到概念描述、不看评测原文），p-dev 有偏乐观的风险——所以在这里跑 p-test。
- **p-test（只跑这一次；此前从未读过、从未参与任何选择）**：

  | 指标 | p-test | p-dev |
  |---|---|---|
  | 动作 | **96.9%** | 97.4% |
  | 端到端 | **95.1%** | 96.6% |
  | 应停却发言 | 1.9% | 1.1% |
  | 换序一致 | 99.8% | 99.7% |
  | 陪伴 / 团队 动作 | 97.7% / 96.3% | 97.7% / 97.2% |
  | 门槛 0.95：覆盖 / 动作 / 端到端 / 应停却发言 | 89.5% / 98.9% / 97.1% / 0.7% | 88.6% / 99.6% / 98.8% / 0.0% |

  p-test 比 p-dev 低 0.5–1.5 个点：提升基本泛化，dev 偏乐观的部分很小。
- **结论：p4 定为发布候选。** 门槛在 p-dev 上选 0.95（覆盖约 89%，其余交给 agent 二次确认），已用 `pin_profile.py` 写进
  `models/laya-participation/ae6718a4/participation.json` 并在 manifest 里固定；`service_check.py` 在 p4 上状态 623/623 逐字相同、
  动作 623/623、人选 296/296 与离线评测一致；`eidolon-laya doctor` 报 `ip_team profile: participation-laya-v1/ae6718a4/min0.95 | ready`。
  p-test 已用过一次，之后的 release 不能再拿它选模型。

## 附：MPS 上的 bf16

p3 检查点上测 37 个 batch（8 条）：bf16 autocast 反而更慢（43 s vs fp32 39 s），预测和 fp32 有 4.7% 的 argmax 不同。不采用。

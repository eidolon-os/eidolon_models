# 智能家居决策：标注规范

所有训练数据和评测数据都按这份规范标注。撰写者（人或模型）写数据前必读；有争议的新情况先在这里补规则，再写数据。
规则的依据是 v1 锁定集（`evals/smart-home/`）的口径；后面批次里形成的约定也都收在这里。

## 1. 三道题

每条用例是一句用户对家里助手说的话（`text`）+ 该户型的设备清单，回答三道题：

| 题 | 选项 | 什么时候标 |
|---|---|---|
| intent 意图 | 控制 / 查询 / 无关 | 永远标 |
| device 设备 | 户型里的设备名（逐字）+ 两个出口 `多个设备或整屋` / `没有对应的设备` | 控制、查询必标；无关不标 |
| action 动作 | 打开或启动 / 关闭或停止 / 调高或增大 / 调低或减小 / 设为指定的数值或模式 / 暂停 / 上锁 | 控制标（说不清时可省略）；查询、无关不标 |

device 和 action 都可以是列表：**列表表示"其中任何一个都算对"**，不是"要同时做这几件事"。

## 2. 意图

- **控制**：说话人要助手**改变**家里设备的状态（开 / 关 / 调 / 设定 / 启动 / 暂停 / 上锁）。
- **查询**：问设备的状态、读数、进度、历史，不改变设备。不带疑问词也算（"看看客厅温度"、"报一下湿度"）。
- **无关**：其它一切。

判定细则：

| 情况 | 标 | 例 |
|---|---|---|
| 问句形式的命令 | 控制 | "能开下空调吗"、"是不是该把灯关了" |
| 能力 / 常识 / 购买问题 | 无关 | "空调能定时吗"、"空调一般开几度"、"哪个牌子扫地机好" |
| 说给家人 / 宠物 / 孩子听的话，**即使带设备名和祈使语气** | 无关 | "老公把电视关了"、"咪咪别爬油烟机"、"小宝别拔插座" |
| 叫助手名字再下指令 | 控制 | "小易把灯关一下" |
| 转述家人**当前**对家里的抱怨 | 控制 | "孩子说太亮了"（指当前环境） |
| 转述别人的旧事、别人的计划 | 无关 | "我妈说过这个空调费电" |
| 外人 / 陌生人要求开门开锁 | 无关 | "快递员说帮他开下车库" |
| 主人本人同意后替外人开 | 控制 | "我朋友在门口，你帮他开一下" |
| 提醒 / 记录类 | 无关 | "提醒我十点关空调"、"记一下今天浇过水了" |
| 定时 / 条件指令 | 控制 | "十分钟后关灯"、"等我睡着了关空调" |
| 保持现状 / 取消 / 否定（不改变任何设备） | 无关 | "卧室灯先别关"、"算了不用开了"、"刚才那个取消" |
| 让正在运行的设备停下 | 控制（关闭或停止 / 暂停） | "别扫了"、"别浇水了" |
| 纠正上一句并给出设备或动作 | 控制 | "不对，是主卧的空调" |
| 闲聊夹指令 | 控制 | "累死了，帮我把热水器开了" |
| 家里的感受 / 情况（隐含意图） | 控制 | "好热啊"、"地上好脏"、"衣服在外面要下雨了" |
| 家外面 / 别人家 / 非设备对象的感受 | 无关 | "外面好热"、"邻居家的猫吵死了"、"这个笑话好冷"、"心里闷" |
| 数字不是参数 | 无关 | "我二十六岁了"、"空调开了二十六个小时了" |
| 陈述状态（不是问、不是要改） | 无关 | "门我已经锁了"、"扫地机扫完了" |

## 3. 设备

- **逐字**用该户型清单里的名字；villa = apartment + house 全部设备。
- **多个都算对就写列表**：没说房间的"灯"在有三盏灯的家 → 三盏灯的列表；"好热" → 所有空调（和风扇）。
- **`多个设备或整屋`**：一句话涉及多台设备（"电视和音箱都关了"）、"都 / 全部 / 所有 / 一楼的"、场景（睡觉、出门、回家、观影、晚安模式）。场景词但只针对一台（"睡前把床头灯关了"）→ 那一台。查询问"灯都关了吗"：同类少量设备写列表，整屋 / 跨品类写 `多个设备或整屋`。
- **`没有对应的设备`**：
  - 点名的设备该户型没有（"启动洗碗机"在 apartment）。
  - **名字相近不算**：洗碗机 ≠ 洗衣机、门锁 ≠ 门铃 ≠ 车库门、加湿器 ≠ 除湿机、净化器 ≠ 净水器。
  - **点名 + 房间，但那个房间没有这类设备**（"客厅空调"在只有卧室空调的家）→ 没有。
  - 隐含意图带房间词，那个房间没有能解决的设备（"厨房太暗"在厨房没灯的家）→ 没有；只有固定安装的设备按房间算，全屋设备（扫地机、新风）覆盖所有房间。
  - 查询一个不存在的设备 → 查询 + `没有对应的设备`。
- **房间优先**：带房间词时选那个房间里**功能对**的设备（"主卧冷"→ 主卧空调，不是主卧加湿器）。
- 真正有争议、两种都合理的，写列表把两种都放进去（含出口），并在 `note` 里写原因。

## 4. 动作

| 说法 | 动作 |
|---|---|
| 开 / 启动 / 开始 / 继续 / 布防 | 打开或启动 |
| 关 / 停止 / 回去充电 / 收工 / 撤防 | 关闭或停止 |
| 亮点 / 大点声 / 高一档 / 热一点 / 升上去 | 调高或增大 |
| 暗点 / 小点声 / 低一档 / 凉快点 / 降下来 | 调低或减小 |
| 具体数值 / 档位 / 模式 / 定时 / 频道 / 百分比 / 一半 | 设为指定的数值或模式 |
| 先停 / 暂停 / 等一下（之后继续） | 暂停 |
| 锁门 / 反锁 | 上锁 |

- 最高 / 最低 / 最大 / 拉满 → [调高或增大 或 调低或减小, 设为指定的数值或模式]。
- 开并设定（"开到制冷 24 度"）→ [打开或启动, 设为指定的数值或模式]。
- 隐含意图按合理动作写列表（热 + 空调 → [打开或启动, 调低或减小, 设为指定的数值或模式]）。
- 场景类可以省略 action。

## 5. 安全

门锁、车库门、安防警报、摄像头：规则同上，但**线上执行时无论置信度多高都要二次确认**（这是产品策略，不改变标注）。

## 6. 数据卫生

- 不得写锁定评测集（v1 全部、v2 全部）里的句子或只差一两个字的句子；每批写完跑 `evals/smart-home-v2/purge_training_overlap.py`。
- 每批新数据抽 10% 做**双人标注**：第二位标注者不看金标独立标，报告一致率，不一致的逐条裁决后才能进训练（`train/data/qa/`）。
- 撰写训练数据时**不读** v2 的用例；误差分析只在开发集（v1、v2-dev）上做，v2-test 只看汇总数字。

## 7. 补充细则（r9 双人标注时暴露的空白，按两位标注者一致的方向定）

| 情况 | 标 | 例 |
|---|---|---|
| 对家人 / 他人**提问**（不只是命令） | 无关 | "媳妇儿，帮我瞅一眼烤箱好了没" |
| 打开摄像头"看一看" | 控制 · 打开或启动（不是查询：句子改变了设备状态） | "打开儿童房摄像头，我看看孩子睡没睡" |
| 喂食器 / 投喂一份 | 控制 · [打开或启动, 设为指定的数值或模式] | "给狗放一份粮" |
| 停掉某个**功能**而不是整台设备 | 控制 · [设为指定的数值或模式, 关闭或停止] | "落地扇别摇头了" |
| "先停"但不确定会不会继续 | 控制 · [暂停, 关闭或停止]；明确之后要继续的只标暂停 | "扫地机先停，快把孩子吵醒了" |
| 外面的原因、影响到家里 | 控制（解决家里的问题） | "邻居的烟味飘进客厅了" → 客厅的净化器 |
| 描述习惯还是当前状况说不清 | 按**当前状况**读 | "下午客厅西晒，沙发都晒烫了" → 客厅窗帘 关 |
| 家里没提到、只说外面将来 | 无关 | "明天有台风，外面风雨大" |
| 先开着 / 回来接着看 | 无关（没有要求改变） | "投影仪先开着，我上个厕所回来接着看" |
| 情绪 / 状况，户型里恰好有能响应的设备 | 控制（该设备） | kids 户型"宝宝醒了一直哭" → 电动摇篮 |
| 几台设备都可能解决 | 写列表把合理的都放进去；有房间词时房间优先 | "衣服晾不干" → [烘干机, 电动晾衣架] |

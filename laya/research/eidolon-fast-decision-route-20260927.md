# Eidolon OS 快速语义决策：路线收敛建议

快照：2026-09-27。范围：单聊、IP Team、后续家居，以及这些场景共用的轻量语义判断。**硬约束：入选模型须开源、可下载权重并能自托管；Jev 仅作技术参考，不调用、不接入、不作为候选。** 此文是选型建议，不授权新训练、外部数据上传或部署。技术更新很快，本文以锁定版本和 Eidolon 自身任务结果为准，不追逐公开榜单。

## 一句话建议

**先用场景代码管许可和流程；只在“当前话语需要谁回应、等待还是澄清”这一处引入快速语义提议。** 保留现有 Laya/RKNN 能力作为首个本地候选，用一小份真实任务样例判断是否值得接入；模棱两可时调用已有的回复 LLM 或追问。家居继续确认后执行。近期不再扩充家居合成训练轮次，不启动 8B CLM 端侧移植，也不同时维护多套决策权重。

这与[模式隔离方案](../../../docs/IP团队/Eidolon模式隔离与公共能力架构评估-20260927.md)一致：单聊、Team、家居各自的 Agent 掌握状态、授权、取消和输出许可；模型只能从其给出的候选里提议。[已有 Laya/CLM 深入对照](semantic-decision-laya-vs-clm-20260927.md)保留技术细节与硬件数据。

## 1. 哪些判断值得交给快速模型

| Eidolon 判断 | 首选执行方式 | 原因 |
|---|---|---|
| 设备/Companion 是否有权、绑定是否有效、场次版本、回合预算、取消、超时 | **代码** | 都有确定性事实，模型不能提供许可。TypeSafe 官方也建议把数字和结构不变量放进代码。[Jev 局限说明](https://docs.typesafe.ai/model-jaggedness/jev-1.13) |
| Team 用户话语应由谁回应、全员等待、还是澄清；单聊是否面向当前 Companion | **快速语义模型的首个目标**，输出只是候选 ID/动作 | 高频、短上下文、封闭候选；现有 mock 缺语义，是产品当前明确缺口 |
| 跨轮代词、讽刺、口头改角、复杂分工、多重否定 | **现有回复 LLM 或澄清**，不要要求小模型一次搞定 | 需要较多间接推理；Jev 官方也列明间接推理、无关长上下文会退化。[官方说明](https://docs.typesafe.ai/model-jaggedness/jev-1.13) |
| 家居“是不是对助手发的命令、哪台设备、什么动作” | 保留 Laya **仅提议**；歧义或高后果操作确认 | 当前 r14 合成验收集自动执行正确率 96.3%、无关误触发 5.3%，未过项目门槛；真实 ASR 未验收。[本仓实验](../train/EXPERIMENTS.md) |
| 语音端点检测、VAD、PTT 打断 | 媒体/声学管线与确定性状态 | 文本 typed choice 不是音频实时判断器；不能用分类模型替代打断和取消屏障 |
| 回复正文、角色演出、开放式解释 | 现有生成式 LLM | 选择模型不生成正文；Team 角色回复执行器已经独立 |

**关键收缩**：不要先建一个统管全部模式的“总裁决模型”，也不要为三个场景各训一套模型。先把一次 Team 判定的输入和输出定窄：最近必要的公开上下文、当前话语、合法成员 ID/角色描述、场次版本；输出 `respond(member_id) | wait | clarify`。长篇历史先由场景 Agent 提取相关状态，模型不读全量记录。

## 2. 最近路线按 Eidolon 适配度排序

| 路线与一手来源 | 优点 | 对 Eidolon 的硬限制 | 当前决策 |
|---|---|---|---|
| [Laya 多语](https://huggingface.co/convaiinnovations/laya-multilingual)：mmBERT 约 322M，typed choice | 本仓已有训练、校准、服务、ONNX/RKNN 与板上实测；动态候选原生支持 | 中文零样本和概率校准不可靠；多选项共享头部 token 预算；家居历史复训暴露合成数据和切分问题；RK3588 与 TTS 同时占 NPU 曾断音 | **唯一先做本地小试的模型**；不立即开新训练 |
| [Kev 0.8B/4B](https://github.com/jaredpalmer/kev)：Qwen＋LoRA＋pointer head | 官方代码和微调配方齐，出口与温度校准有设计；小量领域微调比重训 8B 现实 | 0.8B 官方留出源质量明显弱于 4B；4B 更吃内存；本仓 0.8B 近邻路线在 RK3588 约 4 秒/请求，不能把 CUDA 指标搬到板上 | **观察，不并行推进**；若 Laya 小试失败且云 GPU 可用，再选一个较小版本试 |
| [decider 0.8B/2B](https://github.com/Mapika/decider)：Qwen letter-logit 一次前向 | 完整 typed 接口，版本迭代快；2B 卡有硬题和留出任务分析 | 0.8B 卡自述英语优先；2B v10/v11 在不同任务上互有升降且硬题仍过度自信；无本项目端侧路径 | **不追逐最新版本**；如需第二个 GPU 对照，只固定一个版本，不做训练 |
| [CLM-v0.1-8B](https://github.com/Contrastive-LM/CLM)：Qwen3-8B 双编码器 | 固定候选可缓存，适合大量候选复用/轨迹排名 | 完整栈依赖 8B 编码器；RTX 4090 短热路径约 28 ms 不代表 Opi5max 或长场次；[DeepSWE 头](https://huggingface.co/Contrastive-LM/deepswe-clm-heads-8k)只验证软件工程轨迹 | **不列入当前工程路线**；若未来出现大量候选重排需求再研究 |
| [GLiClass Multilang Edge](https://huggingface.co/knowledgator/gliclass-multilang-edge)：约 140M，含中文的 20 语分类器 | 体积更小；开放标签和描述；零样本意图分类可作为便宜备胎 | 更偏文本标签/多标签，不是现成的“行动＋拒答＋校准”协议；没有本仓 RKNN 质量和延迟证据 | **仅在 Laya 因资源或质量出局时**做一次免训练冒烟，不立即移植 |
| [AnyJev](https://github.com/nokia-applied-research/AnyJev)：复用已有 LLM 隐状态的读出 | 不必重训底座 | 仍须运行 LLM，头/校准按问题适配；官方说明部分任务无法优于平凡基线 | 可供研究，不解决 Opi5max 的首要时延/资源问题 |

公开榜单不可直接排序这些路线：数据、候选文字、是否在训练源上测试、token 长度、温度和硬件都不同。Laya 官方承认多语 checkpoint 零样本 typed 决策接近随机、出厂过度自信；[模型卡](https://huggingface.co/convaiinnovations/laya-multilingual)。Kev 的[0.8B 卡](https://github.com/jaredpalmer/kev/blob/main/docs/model-cards/kev-0.8b.md)与 decider 的[2B 卡](https://huggingface.co/Mapika/decider-2b)也分别写出迁移不足及版本退步。模型“校准”只表示它在某个数据分布和题型上拟过温度，不是 Eidolon 上可免确认执行的保证。

Jev 因闭源托管而**不在上表候选中**。[TypeSafe 文档](https://docs.typesafe.ai/introduction)只用于理解 typed question 接口和已公开的失败模式；Eidolon 不调用其 API，也不以它作为必须追平的基准。

## 3. 用最少成本做一次明确的选择

1. **先拿现有 Team 流程做 60–80 条小样例**：直接点名、无人需答/旁人闲聊、多个成员均合理、需要澄清四组各约 15–20 条。尽量来自脱敏真实话语和当前角色配置；原句、成员名单、正确可接受动作、候选版本都保存。这是**选型冒烟**，不是安全认证或统计泛化声明。
2. **只跑两个已有选手**：当前 mock/简单规则和现有 Laya 多语 checkpoint。使用同一候选和中文题目。只看逐例错误：错叫人、该等待却回应、该澄清却强答、角色或名单改变后引用旧成员。无需重训、无需大范围扫模型，也不调用 Jev。
3. **若 Laya 已够用**：在 Agent 中只接一处提议端口，低把握或冲突交给已有 LLM/澄清；保留 mock 回退。把候选校验、版本校验、取消、回复预算写在 Agent，不让模型文本控制设备或身份。RK3588 上先避开与 TTS 抢三核的已知配置。
4. **若 Laya 错误集中且可学习**：收集这些特定错误附近的少量真实标注数据，最多一次定向微调，并在独立小留出集上看是否明显改善。若错误是跨轮复杂推理、角色状态丢失或许可事实缺失，优先修场景上下文/代码，别扩大训练集。家居继续按[真实数据方案](../train/REAL-WORLD-EVAL-PLAN.md)确认后执行；不要用新的合成轮次重测旧验收集。
5. **若 Laya 仍不行**：短期让现有 LLM 只处理这些模糊 Team 轮次，不接入第三套实时模型。只有模糊轮次比例、延迟或 token 费用实测成为瓶颈，再试一个 GPU 决策模型；优先 Kev 0.8B 或固定版 decider 2B 中**一个**，按目标硬件和中文样例选，不把 CLM/DeepSWE/多个权重一起推进。

停止规则很简单：一轮小试后，能明确给 Team 带来正确回应/等待/澄清且资源不影响现有语音，就接入 shadow；不能明确改善，就保持 mock＋已有 LLM/澄清，不花训练算力。上线前仍需对权限与误发言作必要验收，但不先建设大型通用 benchmark、完整多任务模型或适配层矩阵。家居的自动执行另受其安全门槛约束，小样例不能替代真实用户验收。

## 4. 选型后的长期形态

Eidolon 可保留一个窄的 `DecisionPort`：输入是场景准备好的短状态和**已授权候选**，输出是带分数的提议；端口不承诺任何模型家族，也不新增跨场景全局语义权威。单聊、Team、家居各自决定什么时候调用、低把握怎么办、许可如何核验。这样未来若换 Laya、Kev、GLiClass 或其它开源自托管权重，只改这个窄端口和该场景的阈值/证据，现有身份、设备、角色和执行流程不会跟着换。

优先投入的不是继续造训练数据，而是**一份真实问题清单＋逐例失误复盘**。当前最可能获得产品收益的单点，是让 Team 从固定 mock 变成能识别“点名、沉默、澄清”的受约束语义裁决；家居高风险免确认执行与长场次动态改角放在后面。

P0 · 相对调节必须以真实状态为基准

第 13–16 轮加湿器结果为 10% → 10% → 20% → 10%。第 14 轮重复“调大一点儿”未增加；加入“再”后才增加。首次前置状态未保存，不能判断第 13 轮是否反向减小。线上与本地同哈希的 LLM fallback 只传设备身份、能力与会话上下文，未传实时 speed；Hub 虚拟 Provider 的 fan_speed.set 是绝对赋值。这是协议/状态语义缺口，不能仅靠增加训练语料解决。

改进与验收：建议将相对意图表示为增量，由执行层读取最新状态并校验/原子执行；状态不可读时澄清，不让 LLM 猜绝对值。补初始 0/10/30/90/100、连续增减、不带“再”、会话重启、外部改值、重试幂等、上下限等状态序列断言。

P1 · 执行后的否定与撤销要有清晰反馈

第 3 轮已经打开客厅灯，第 4 轮“不开客厅的”（原文为“不开客厅的。”）回复“已取消，本次没有执行设备操作”，只取消本轮，不撤销已执行动作。第 9 轮只打开主卧，未关闭之前打开的客厅。当前行为遵循“否定不等于反向操作”，但用户容易把改口理解为纠正已完成的操作。

改进与验收：明确区分待执行取消、已执行后的改口、明确撤销。已执行时提示“客厅灯刚才已打开；这次没有新操作”，必要时问是否关闭；不能自动把“不打开”变成“关闭”。补 pending/executed、单句纠正/跨轮纠正、否定+新目标、撤销失败的序列测试。

P1 · 路由比模型速度更限制 NPU 覆盖

20 轮中 3 轮由 Laya 直接完成；3 轮 NPU 后转 LLM；14 轮未调用 NPU，其中 12 轮被 explicit_reference 规则挡住，2 轮 semantic_required。明确设备名的“开灯”“关主卧的”“加湿器调大”等直接退到 LLM。纯 NPU 承接率 15%，曾调用 NPU 30%，最终 LLM 85%。这些比例只代表本次 20 轮。

改进与验收：先明确哪些请求应走单轮 Laya、哪些走续轮 Laya、哪些必须兜底；仅换 c10 不会自动修复前置规则。增加真实 Agent 路由集，断言目标、动作、拒识原因、是否调用 NPU、最终是否 LLM；同时看安全误执行和正确承接率。

P1 · 补齐候选选择和目标切换的口语分布

“客厅的”选灯 0.9883、“床头的”0.9623，直接执行；“客厅”选空调 0.9408 被 0.95 阈值拒绝，再调用 LLM。第 11 轮“开床头的”走 follow，0.7533 后兜底；它涉及目标变化，不能只看动作“打开”分数就放行。

改进与验收：训练加入不同房间/设备排列、裸房间名、的/吧/就那个、床头别名、同房间多灯、换目标且换动作等对照。禁止简单降低全局阈值；用独立校准集分别评估 pick/follow、否定/无目标/越权旧目标误执行。今天样本可作回归种子，训练扩写和冻结验收必须按会话/模板/家庭布局隔离。

P1 · 连续讲话的等待需要独立测量

第 11 轮从最终转写到交付 2.285 秒，Agent 自身 0.983 秒；进入 Agent 前约 1.265 秒。第 12 轮交付 1.951 秒，进入 Agent 前约 0.742 秒，且转写完成时上轮尚未结束。第 11 轮识别后 43 毫秒又出现新 VAD 起点。Channel 在 on_user_turn_completed 内 await 全链路且 interruption=false；可确认等待发生在模型外，但现有日志不能唯一拆分 turn-finalization、轮次调度及队列等待。

改进与验收：增加 final_received、turn_committed、queued、dequeued、Agent/Hub/Provider start/end 时间戳。Mac 模拟 0/100/300/800 毫秒间隔连续 2–5 条、动作纠正、顺序依赖和中途断开；保证不丢句、不合并误执行、不乱序，避免简单并行破坏上下文。

P2 · 语音与端侧闭环不能由文本成功率替代

“开飞机”被判非家居，随后“开洗衣机”启动洗衣机。这可能是 ASR 错误，也可能确实说了飞机；没有原音频无法裁定。“开洗衣机”被映射为 operational.start，需要明确产品里“开机”与“启动程序”的预期。结果是服务端交付成功，尚非 Korvo 展示 ACK。设备状态存于虚拟 Provider，不能据此宣称物理家电动作完成。

改进与验收：增加洗衣机/飞机等近音的真实音频集，含距离、噪声、打断和连续讲话；对可疑近音澄清，不自动改写执行。增加端侧收到/渲染 ACK、Hub 命令 body/receipt、前后状态和 Provider 类型的可关联审计，区分已是目标状态与实际发生变化。

现有测试覆盖与建议补集

本次抽查：continuation/eval/locked.jsonl 共 44 条，没有 fan_speed 或加湿器样本；Hub 的风速测试覆盖 set(value=80)，Agent 有电视音量相对 step 和模拟 executor。这些是有用的组件测试，但不能证明“语音→相对意图→多轮实时状态→执行回执”正确。c10 另有 216 条封存合成验收及历史门槛，不能与这个 44 条集合混为一谈，也不能替代音频和状态序列测试。此处不是对全仓所有评测集的穷尽审计。

  1. 保留今天 20 轮为真实会话回归种子，给每轮标注 expected target/action/state delta、允许澄清、禁止副作用；“飞机”待音频确认后才标 ASR 错误。
  2. 另建状态序列集，优先加湿器连续增减、目标切换、取消/撤销；验收最终状态与事件次数，不只检查 outcome。
  3. 建立真实 Agent 路由评测，c4/c10 同输入同上下文比较接受率、拒识与错误执行；先在 Mac 做高精度基线，不把候选离线分数等同于部署收益。
  4. 建立音频/调度集，逐项测 ASR final、turn commit、队列、模型、执行与端侧呈现；纯文本集合无法覆盖连续说话与近音识别。
  5. 训练集与冻结验收按会话/模板/房间组合隔离。今天原句若进训练，只能作为已知回归项，不能再声称是独立泛化验收。

证据边界与可追溯性

Agent turn_id 与结果为直接日志；Channel 最终转写按文本与时间匹配。Laya 与 Hub HTTP access 不带 turn_id，本报告按唯一请求时间窗关联。各服务使用嵌入时间戳；Hub access 无嵌入时间，用 journald 时间，故不据它计算精确执行耗时。

线上 command.py、llm_fallback.py、laya_continuation.py、Channel smarthome.py 与 Hub providers/virtual.py 的 SHA-256 均与本地一致。只读 SQLite 确认同一用户的虚拟设备状态；当前快照只证明采集时状态，不能反推每轮前置状态。加湿器最终 on=true/speed=10，洗衣机 run_state=running，床头灯 on=true、客厅灯与主卧灯 on=false。未读取到每轮物理设备回执或 Korvo 渲染 ACK。

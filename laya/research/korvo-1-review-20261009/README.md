## 链路与模型输出能确认到什么程度

实际链路：Korvo 音频 → FireRed pVAD / Bailian FunASR → Channel 完整文本 → Agent 权限与快照 → Laya c10 NPU → 直接接受或携带 laya_handoff 转 LLM → 命令校验 → Hub → Channel Provider 结果投递。

- 首轮 3 个问题：intent、device、action；后续每轮 5 个问题，增加 context_device 和 follow/pick。每轮只有一个批量 HTTP 请求，不是 5 次独立 HTTP 往返。
- 第一轮 Laya 服务 462ms、累计 463 tokens；其余 16 轮 736–810ms、累计 961–1045 tokens。这里 tokens 是多个问题累计量，不是单条上下文长度超过 512；所有日志均 `truncated=-`。
- 12 次兜底原因：low_confidence 9 次；unsupported_command、multiple_devices、pending_not_resolved 各 1 次。没有因为 RulesInterpreter 前置筛选而绕过 Laya。
- 配置 min_confidence=0.8，但 context-v2 实际接受下限被代码提升：普通 proposal 0.99，pick/follow 0.95，follow 另要求 control intent ≥0.99。配置表面值不能代表实际行为。
- 五次直接接受对应“主卧”“客厅空调打开”“主卧空调打开”“关闭空调（第一次）”“客厅”。日志未保留 resolution，因此不能把每个直接接受分支精确归因到 pick、follow 或 direct。
- **原始输出缺失**：生产 `interpretation_record_path: ""`。没有这 17 轮的分类 choice、top3、概率、实际上下文快照或完整 LLM 工具参数，无法事后恢复。路由拒绝原因不是完整模型输出；low_confidence 也不能说明具体哪个分类低。代码确实传递 laya_handoff，但本次不能证明 LLM 采纳了其中哪些建议，更不能声称因此提高了准确率。
- Hub 日志能对齐 14 次 execute HTTP 200；已检查的 smarthome SQLite 只持久化 virtual_devices 当前状态，没有逐轮历史回执。本报告命令语义来自 Agent fallback / VoiceResult；不虚构缺失参数，也不将其当作物理家电动作验证。

## 体验缺口

### 1. 绝对值与增量混淆，优先修复

第 2 轮 ASR 是“调大到音量30%。”，LLM fallback 明确选择 `volume.step`，最终回复音箱音量 50。按“到 30%”表达，应设置绝对目标 30。日志不足以证明内部 delta 恰为 +30 或此前值为 20，但可确认选择了相对调节，并且结果不是 30。Laya 该轮因为低置信度退出；不能把错误直接算作 Laya 原始预测错误。

需补“调到 / 调大到 / 增加 / 降低 / 降到”成对用例，以及量纲、边界和真实状态验证。无须先训练；优先修正参数语义、工具约束和执行前校验。

### 2. 近期设备焦点利用不稳定

第 6–8 轮连续操作电视，第 9 轮“声音小一点”仍询问电视还是音箱；距离上轮只有约 7 秒，明显在 30 秒窗口内。第 9 轮 Laya low_confidence、LLM clarification。应作为不必要澄清候选修复，而不能简单归因于上下文过期。

第 15 轮“关闭空调”承接主卧并成功；4 秒后完全相同的第 16 轮却转 LLM 要求选房间。用户可能是在重复命令，也可能希望关另一台；正确策略应结合最近目标与设备状态，保持可解释、一致的追问或幂等反馈。不能未经明确表达就自动切换到另一台。

第 4 轮“关了吧”最终由 LLM 正确承接音箱，但 Laya adapter 以 multiple_devices 退出。当前代码在单句 device=MULTIPLE 时可以阻止上下文分支承接，值得针对这类省略主语复现。实际概率缺失，暂不能断言该处就是唯一根因。

### 3. 澄清后的完整重述处理不够灵活

第 10 轮用户已明确说“电视的声音小一点”，仍因 pending_not_resolved 转 LLM。代码在 pending 未被 pick 消解时会先退出，再考虑正常 direct 结果。这是有意保守的流程，但对“重新说完整命令”的交互不友好。需区分“回答选择”和“新完整命令”，确保不会继承错误的旧动作。

### 4. 简单口令的直接接受覆盖不足

音箱开机，以及三次明确的电视开关均以 low_confidence 转 LLM。c10 已投入真实使用，但本样本只有 29.4% 绕过 LLM，价值主要体现在 5 轮直接完成。另 12 轮增加了前置推理时间，是否改善 LLM 判断目前没有证据。不能只用“调用了 Laya”代表发挥了价值，也不能只靠全局降阈值提高通过率。

应在固定 c10 权重下先记录分头概率，按设备与动作分析误拒绝/误接受，再调整接受策略。对 unsupported_command 需分清分类错误、设备动作映射缺失与参数解析失败。

### 5. 语气/状态查询需要单独覆盖

“洗衣机关了吧？”被当作停止命令执行。它也可能是询问是否已关闭。仅凭 ASR 标点无法判定实际意图；应补充查询/祈使最小对照和语音样本，避免把所有此类句子直接算成功控制。
